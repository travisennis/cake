# Investigate malformed arguments in stream-json function_call events

## Summary

While parsing the stream-json transcript of cake session 4988adce
(2026-07-12, ahm task 181 run), one `function_call` event of five for the
Edit tool had an `arguments` string that is not valid JSON
(json.loads fails with "Expecting property name enclosed in double quotes"
around char 1313); the other four parsed cleanly. Either cake serialized
the event without validating or escaping the model-emitted tool arguments,
or malformed model output was passed through verbatim. Consumers of
`--output-format stream-json` (orchestrators such as ahm task work parsers,
session capture, transcript tooling) need every event line to be valid JSON
with machine-readable fields.

## Relevant Files

- `src/types/session.rs` — `FunctionCallData` struct (arguments: String), `StreamRecord::from_conversation_item()`, `StreamRecord` / `SessionRecord` serde derives
- `src/types/conversation.rs` — `ConversationItem::FunctionCall` definition
- `src/clients/agent_observer.rs` — `stream_record()` serializes `StreamRecord` via `serde_json::to_string()`
- `src/config/session.rs` — session JSONL persistence via `serde_json::to_writer()`
- `src/clients/responses.rs` (line ~448) and `src/clients/chat_completions.rs` (line ~205) — where model-emitted arguments enter `ConversationItem::FunctionCall`
- `src/types/session_tests.rs` — existing round-trip tests (no hostile-argument coverage yet)

## Fix Direction

Reproduce from the captured session. If serialization is at fault, fix the
escaping so `arguments` always round-trips. If the model emitted malformed
arguments, decide the contract: repair, or emit the raw string under an
explicit field (for example `arguments_raw` plus a `parse_error` marker) so
consumers can detect it without failing. Add a test that round-trips tool
arguments containing quotes, backslashes, newlines, and control characters.

## Acceptance Notes

- [x] Root cause identified (serializer vs model passthrough) and recorded
- [x] Every stream-json event line round-trips through a strict JSON parser
- [x] Malformed model arguments, if passed through, are explicitly marked
- [x] Round-trip test covers hostile argument content

## Root Cause

The malformed `arguments` string in session `4988adce` (line 84) is model output passed through verbatim, not a serialization bug. `src/clients/responses.rs::parse_function_call_output()` and `src/clients/chat_completions.rs::parse_choices()` copy the model-emitted `arguments` string into `ConversationItem::FunctionCall` without validation. `AgentObserver::stream_record()` then serializes `StreamRecord` via `serde_json::to_string()`, which correctly escapes the raw string as a JSON value; the enclosing JSONL line is valid JSON. The nested `arguments` string itself, however, was truncated/cut off by the model (`...}],<`), so consumers parsing it as JSON fail.

## Fix Summary

- Added `arguments_parse_error: Option<String>` to `FunctionCallData` (defaulted, omitted when `None`) so stream-json/session records can explicitly flag malformed model arguments while preserving the raw `arguments` string.
- `StreamRecord::from_conversation_item()` now validates `arguments` as JSON when converting from `ConversationItem::FunctionCall` and populates `arguments_parse_error` on failure.
- Added tests for valid arguments (no marker), malformed arguments (marker present, enclosing line still valid JSON), and round-tripping hostile content (quotes, backslashes, newlines, control characters).
- Updated `docs/design-docs/streaming-json-output.md` to document `arguments_parse_error`.
