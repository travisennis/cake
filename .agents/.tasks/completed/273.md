# Handle parent components safely in new Write paths

## Summary

At commit `6e69b45`, Write-tool validation for nonexistent paths reconstructs lexical components by repeatedly taking `file_name()`. Parent-directory (`..`) components in a path whose preceding directory does not exist can disappear during reconstruction, causing the file to be created at a different in-scope location than the model requested.

## Evidence

- `src/clients/tools/write.rs:115-124` — existing paths use shared canonical validation, but nonexistent paths take a separate reconstruction path.
- `src/clients/tools/write.rs:126-142` — the validator walks upward until an existing ancestor and records only components returned by `file_name()`; `..` is not preserved as a normal file-name component.
- `src/clients/tools/write.rs:180-190` — recorded components are appended to the canonical ancestor without lexical normalization or rejection of parent components.
- Example shape: `<cwd>/missing/../other/file.txt` with nonexistent `missing` can reconstruct beneath `<cwd>/missing/other/file.txt` rather than the requested normalized `<cwd>/other/file.txt`.
- `src/clients/tools/write.rs` tests cover ordinary nested creation and boundary checks but not parent components across nonexistent ancestors.

## Fix Direction

Normalize or reject parent-directory components before reconstructing a nonexistent write target, then validate the deepest existing ancestor and final destination consistently with shared path policy. Preserve the security property that writes cannot escape allowed roots and preserve ordinary nested-directory creation. Ensure `mutating_target` and actual execution resolve to the identical path so same-target scheduling remains correct. If symlink races require stronger open-at/no-follow semantics, record that separately rather than broadening this localized correctness task.

## Acceptance Notes

- [ ] A regression test covers `..` following a nonexistent component and proves the tool either targets the normalized requested path or returns a clear error.
- [ ] `mutating_target` and `execute_write` agree on the resolved destination.
- [ ] Traversal outside the workspace/temp/settings write roots remains rejected.
- [ ] Ordinary new nested files, existing-file overwrites, and read-only additional directories retain current behavior.
