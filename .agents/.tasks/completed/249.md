# Add Schema-Constrained Final Output

## Problem

Add a non-interactive CLI flag that constrains cake's final response to a JSON document valid against a caller-supplied JSON Schema.

ahm is adding delegation commands such as `ahm task groom` and `ahm audit` that hand procedure prompts to a coding agent and mechanically apply the structured result. cake is ahm's default work agent, so it needs first-class parity with other supported agents that already provide schema-constrained final output. Prompt-only JSON instructions are not reliable enough for this contract.

The schema must constrain only the final response, specifically the `result` field of the `task_complete` stream-json event. Intermediate reasoning, tool use, and multi-turn agent behavior should remain unchanged.

## Proposed CLI Contract

```bash
cake --output-schema <schema.json> --output-format stream-json "<prompt>"
```

- `--output-schema <path>` points to a JSON Schema file describing the final response shape.
- The final response must be exactly the schema-valid JSON document, with no Markdown fences or surrounding prose.
- The run remains fully agentic; only the final assistant result is constrained.
- The flag applies to non-interactive runs and should compose with `--output-format stream-json` and `--resume <session-id>`.
- Prefer native structured-output support from the active backend when available. If native support is not available, a bounded validate-and-retry loop is acceptable as an initial implementation, provided failure is loud and machine-detectable.

## Error Handling

- Unreadable schema file fails before the run starts with a nonzero exit and clear human-readable error.
- Invalid schema file fails before the run starts with a nonzero exit and clear human-readable error.
- A final response that cannot be made schema-valid, including refusal, truncation, or retry exhaustion, must fail with both a nonzero exit and an explicit failure event in the stream (see Decision).
- Callers must never receive a successful `task_complete.result` that silently contains non-conforming prose.

## Decision

Recorded 2026-07-08 during grooming (maintainer-approved). Full rationale in [ADR-012](../../../docs/adr/012-schema-constrained-final-output.md); delivery steps in the ExecPlan referenced in front matter.

- **Enforcement**: local validation is authoritative, using the `jsonschema` crate (new dependency, `default-features = false`, no remote/file `$ref` resolution). Native backend structured output (Responses `text.format` json_schema, Chat Completions `response_format` json_schema, both strict) is attached only to corrective finalizer turns as best-effort acceleration.
- **Schema dialect**: JSON Schema draft 2020-12 as implemented by the `jsonschema` crate. Schemas must be self-contained. Backends' native strict modes support only a subset; cake passes the schema through unmodified and falls back to unconstrained retries if the provider rejects it (HTTP 400).
- **Keeping intermediate turns unconstrained**: the agent loop runs unchanged; the schema requirement is injected as developer context. Validation happens only on the final (no-tool-call) message. If it fails, cake runs at most 2 corrective turns with tools disabled (no tools offered on the request) and the native constraint attached, appending validation errors as a corrective message each time.
- **Failure contract**: both channels, not either — a `task_complete` record with new additive subtype `error_output_schema` (`is_error: true`, validation detail in `error`) and process exit code 1 (agent error). Pre-run schema file errors (unreadable or invalid) exit 3 (input error) before `task_start` is emitted.
- **Scope of the flag**: cake is a one-shot non-interactive CLI, so `--output-schema` applies to every run and composes with all `--output-format` values (`text` prints exactly the JSON document; `json` keeps `result` as a JSON string containing the document) and with `--continue`/`--resume`/`--fork`. The schema is per-invocation and not persisted to the session; corrective turns persist as ordinary conversation items.

## Relevant Files

- `src/main.rs` - `CodingAssistant` clap struct: add `--output-schema`, pre-run schema load/compile, thread the compiled schema to the agent.
- `src/clients/agent/agent_loop.rs` - `Agent::send` final-message branch (the `function_calls.is_empty()` return): local validation and the bounded corrective loop.
- `src/clients/responses.rs` / `src/clients/responses_types.rs` - `text.format` json_schema request shaping for finalizer turns.
- `src/clients/chat_completions.rs` / `src/clients/chat_types.rs` - `response_format` json_schema request shaping for finalizer turns.
- `src/types/session.rs` - new `TaskOutcome`/`TaskCompleteSubtype` variant `error_output_schema`.
- `src/exit_code.rs` - classify pre-run schema errors as input error (3) and schema-exhaustion as agent error (1).
- `Cargo.toml` - add `jsonschema` with minimal features.
- `docs/design-docs/cli.md` - document the flag and final-message-only semantics.
- `docs/design-docs/streaming-json-output.md` - document the new `task_complete` subtype and failure contract.

## Implementation Notes

- ADR-012 (`docs/adr/012-schema-constrained-final-output.md`) records the decision; the ExecPlan in front matter is the delivery plan. Both exist — review ADR-012 and accept it (`ahm adr accept 012`) before code changes begin.
- Validate the schema before starting the run.
- Keep compatibility with existing stream-json consumers: the new flag and subtype are additive; consumers keying on `is_error` are unaffected (same precedent as ADR-011's `interrupted`).
- The `jsonschema` dependency affects binary size, which is audited; measure before and after and keep features minimal.

## Acceptance Notes

- [x] `cake --output-schema <file> --output-format stream-json "<prompt>"` yields a `task_complete` event whose `result` is a JSON document valid against the schema.
  Covered by wiremock-backed output-schema agent tests and backend request snapshots.
- [x] The `task_complete.result` has no Markdown fences or surrounding prose.
  Covered by the fenced-JSON correction test and exact trimmed-document validation path.
- [x] The same behavior works on `--resume <session-id>` runs.
  Covered by persisted conversation/session behavior and per-invocation schema attachment tests; the schema itself is intentionally not persisted.
- [x] Unreadable schema files fail before the run starts with a nonzero exit.
  Manually verified with a missing schema path: printed only the schema read error and exited 3.
- [x] Invalid schema files fail before the run starts with a nonzero exit.
  Manually verified with `{"type":123}`: printed only the schema validation error and exited 3.
- [x] Refusal, truncation, retry exhaustion, or otherwise unsatisfiable output exits 1 and emits a `task_complete` record with subtype `error_output_schema` that stream-json callers can distinguish from success.
  Covered by output-schema exhaustion tests, exit-code tests, and `handle_agent_turn_result` stream record tests.
- [x] Help text documents `--output-schema` and its final-message-only semantics.
  Manually verified with `cargo run -- --help | rg -C 2 -- "--output-schema"`.
- [x] CLI and stream-json design docs are updated for the new contract.
  Updated `docs/design-docs/cli.md`, `docs/design-docs/session-management.md`, and `docs/design-docs/streaming-json-output.md`.
