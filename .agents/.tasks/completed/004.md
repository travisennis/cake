# Fix mtime-Based Newest Session Resolution Fragility

**Problem:** `load_latest_session()` picks the session file with the highest `modified` timestamp via `max_by_key`. This is fragile due to `touch`, clock skew, and backup/restore operations.

**Files involved:**
- `src/config/data_dir.rs` (lines 164–198)

**Fix:** Stop relying on filesystem mtime. Options:
1. Add a `created_at: DateTime<Utc>` field to `Session`, persist it, and use it as the sort key.

**Acceptance Notes:**

- [x] Both `load_latest_session()` and `load_latest_session_any_directory()` sort by the `timestamp` field from the session_meta JSONL record instead of filesystem mtime.
- [x] Added `timestamp: DateTime<Utc>` field to `SessionFileHeader` so the sort key is available from the header parse pass without a full session load.
- [x] All 11 existing `data_dir` tests pass without modification.
- [x] The `timestamp` field already existed on `SessionMeta` — no schema migration needed.
