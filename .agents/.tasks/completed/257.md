# Support linked git worktrees in the sandbox profile

## Summary

When cake's workspace is a linked git worktree (created with `git worktree
add`), the workspace `.git` is a file whose `gitdir:` pointer targets
`<parent>/.git/worktrees/<name>`, and git also needs the common dir
`<parent>/.git` (objects, refs, config; the per-worktree dir holds index,
HEAD, MERGE_MSG). The sandbox profile only allows the workspace subtree plus
home-level git config (`append_git_rules` in
`src/clients/tools/sandbox/macos.rs`), so every git command inside a linked
worktree fails with `fatal: ... Operation not permitted`.

Observed 2026-07-12 running `ahm task work` inside a linked worktree of the
ahm repository (cake session 4988adce): implementation and review phases
succeeded, but the commit handoff could not run any git command and had to
hand back manual commands. The failure surfaced only at the end of a long
run, at the first git invocation.

## Relevant Files

- src/clients/tools/sandbox/macos.rs (profile construction, `append_git_rules`)
- src/clients/tools/sandbox/mod.rs (path allowlist assembly)
- src/config/worktree.rs (cake-managed worktrees; external worktrees take a different path)

## Fix Direction

At sandbox profile construction, detect that `<workspace>/.git` is a file,
parse its `gitdir:` pointer, resolve the target directory and the
`commondir` file inside it, and add read/write rules for both the
per-worktree gitdir and the common git dir. Cover cake-managed worktrees and
externally created ones. If the gitdir cannot be granted, report it at
session start rather than failing at the first git call late in a run.

## Implementation Notes

Added `resolve_linked_worktree_dirs()` and `resolve_worktree_commondir()` in
`src/clients/tools/sandbox/mod.rs`. At sandbox config construction time
(`build_with_policy`), if `<cwd>/.git` is a file, the function reads the
`gitdir:` pointer to find the per-worktree gitdir, then reads its
`commondir` file to find the common git directory. Both directories are
added to the writable set so git commands can operate under the sandbox.

Key design decisions:
- The common dir is resolved solely from the `commondir` metadata file
  written by git, NOT inferred from path structure (no fallback).
- Early warning is emitted at session start via `load_run_resources`
  before any Bash tool call, so the user sees it before git first fails.
- Resolution is platform-agnostic (benefits both macOS Seatbelt and
  Linux Landlock).
- `resolve_linked_worktree_dirs` is `pub` so it can be called from
  `main.rs` for the early warning.

19 tests cover this functionality:
- Normal repo with .git as directory → empty (no-op)
- Missing .git → empty (no-op)
- Parsed gitdir + commondir → both directories returned
- Relative gitdir paths → correctly resolved
- Non-existent gitdir target → empty (warns)
- Missing gitdir: line in .git file → empty (warns)
- Malformed .git file → empty (warns)
- Missing commondir file → None (warns)
- Empty commondir file → None (warns)
- Unresolvable commondir path → None (warns)
- build_with_policy integration → linked dirs in writable set
- Real git worktree via `git worktree add` → exact gitdir and common dir in writable set
- macOS profile generation with real linked worktree → allow rules in Seatbelt profile

## Independent Review Findings (2026-07-12)

**Finding 1 (HIGH): Session-start warning is tracing::warn! only, not user-visible.**
RESOLVED: Added `eprintln!` in `load_run_resources` (src/main.rs:503-514) that
fires when `.git` is a file but resolution returns empty. Detailed diagnostics
still go to the log file via tracing::warn!. The `eprintln!` goes to stderr,
which does not corrupt machine-readable stdout output modes (JSON, stream-json).

**Finding 2 (MEDIUM): Real-worktree test doesn't enforce sandbox.**
RESOLVED: Added `test_profile_includes_linked_worktree_dirs` in `macos.rs` that
creates a real git linked worktree, builds a SandboxConfig through the full
resolution chain (build_with_policy), generates the macOS Seatbelt profile, and
verifies the profile text contains allow rules for both the common .git dir and
the exact per-worktree gitdir parsed from the .git file. This is a deterministic
profile-generation test that does not require `sandbox-exec` to be functional.

End-to-end enforcement (running actual git commands through `sandbox-exec`)
requires a macOS host where `can_enforce_platform_sandbox()` returns true. The
existing `test_sandbox_workspace_write_allows_write_in_cwd` in bash_tests.rs is
the pattern for such a test but is skipped when the probe fails.

Task remains Pending due to this platform gap (see blocker in Acceptance Notes).

**Finding 3 (LOW): Real-worktree test asserts any descendant, not exact gitdir.**
RESOLVED: The `resolve_linked_worktree_with_real_git_worktree` test now reads
the `.git` file from the worktree, parses the `gitdir:` line, canonicalizes the
path, and asserts that exact path (not any descendant) is in config.writable.
