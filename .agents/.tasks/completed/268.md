# Clean up macOS sandbox profile temporary files

## Summary

At commit `6e69b45`, every sandboxed Bash command on macOS intentionally forgets its generated Seatbelt profile `TempPath`. This keeps the profile alive through spawn but leaks one `.sb` file per invocation until the operating system eventually cleans the temp directory, which can accumulate heavily in long-running or high-volume sessions.

## Evidence

- `src/clients/tools/sandbox/macos.rs:403-405` — every application writes a fresh profile and converts it into a `TempPath`.
- `src/clients/tools/sandbox/macos.rs:415-434` — the command is reconfigured to invoke `/usr/bin/sandbox-exec -f <profile>`.
- `src/clients/tools/sandbox/macos.rs:436-438` — `std::mem::forget(profile_path)` deliberately prevents deletion, with no later ownership or cleanup path.
- `.agents/.tasks/completed/097.md` explicitly left per-command sandbox-profile lifetime for separate follow-up rather than resolving it.

## Fix Direction

Give the profile file an owner whose lifetime covers process spawn/use and then removes it deterministically after it is safe for `sandbox-exec`. Preserve generated profile contents, sandbox availability errors, and command behavior. Prefer a lifecycle guard tied to the spawned command or execution scope; do not switch to inline profiles or weaken Seatbelt enforcement without an explicit design decision. If `sandbox-exec` requires the file for the full child lifetime rather than only startup, verify that fact and retain it until child completion.
