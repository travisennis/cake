# Return a Typed Outcome Instead of Fabricating Assistant Messages

**Created:** 2026-07-07
**Source:** 2026-07-07 backlog triage (bitter-lesson audit V11 / Phase 2 item 10).

## Problem

`resolve_assistant_message` (`src/clients/agent_state.rs`, around line 117) invents prose such as "The task may have been partially completed but was cut off during reasoning" and returns it as if the model produced it. The harness is speaking in the model's voice: downstream consumers (session records, stream-json clients, users reading text output) cannot distinguish fabricated text from real model output.

## Fix Direction

- On incomplete/cut-off responses, return a typed outcome instead of synthesized assistant prose — extend `TaskOutcome` (or the equivalent completion surface) with a variant that names the condition (e.g. cut off during reasoning, no output items).
- Text mode may still print an explanatory line, but attributed to cake, not rendered as an assistant message.
- Session records and stream-json must not contain harness-authored text tagged as assistant output.
- Task outcome and stream/session shapes are documented compatibility surfaces: changes must be additive/versionable; check whether an ADR note is warranted (likely a small one given `TaskOutcome` precedent from task 055).

## Relevant Files

- `src/clients/agent_state.rs` — `resolve_assistant_message`
- `src/types/` — `TaskOutcome` / completion data
- `src/cli/output.rs` — text rendering of the new outcome
- Session/stream record types and snapshot tests
- `docs/design-docs/conversation-types.md`, `docs/design-docs/streaming-json-output.md`

## Changes

### `src/types/session.rs`
- Added `CutOff` variant to `TaskCompleteSubtype`
- Added `TaskOutcome::CutOff { detail: String }` variant
- Added `CutOffError` error type for the agent loop to return
- Updated `is_error()`, serialization, and deserialization for the new variant

### `src/types/mod.rs`
- Exported `CutOffError`

### `src/clients/agent_state.rs`
- Changed `resolve_assistant_message()` from returning fabricated `String` to returning `Option<String>`.
- Updated unit tests: `None` is returned when no assistant message exists.

### `src/clients/agent/agent_loop.rs`
- Imported `CutOffError`
- `resolve_final_message_or_correct`: when `resolve_assistant_message()` returns `None`, returns `Err(CutOffError(...))` with a descriptive detail.
- Added `cut_off_error()` helper function that produces appropriate detail based on history (empty, reasoning present, or no message).

### `src/main.rs`
- `handle_agent_turn_result`: catches `CutOffError` and calls `emit_cut_off_agent_turn`
- Added `emit_cut_off_agent_turn`: calls `run_stop_hook` (not error hook) and emits `TaskOutcome::CutOff`
- `task_outcome_for_error`: maps `CutOffError` to `TaskOutcome::CutOff` (defense-in-depth)
- `execute_agent_turn`: converts `CutOffError` to `Ok(detail)` for the render result, since the outcome is already emitted by `handle_agent_turn_result`

### `src/types/session_tests.rs`
- Added `task_outcome_serializes_cut_off`, `task_outcome_deserializes_cut_off`, and `task_outcome_cut_off_requires_error` tests
