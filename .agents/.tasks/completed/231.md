# Make CI Docs Lint Blocking

## Problem

The CI Docs job runs `panache lint . --quiet || true` (.github/workflows/ci.yml, Docs job). The `|| true` makes the lint advisory-only — it can never fail the build, so doc lint enforcement is decorative.

## Relevant Files

- `.github/workflows/ci.yml` — the Docs job containing `panache lint . --quiet || true`

## Fix Direction

Remove `|| true` and add `--check` to the CI command. Investigation revealed that `panache lint` without `--check` always exits 0 (it warns but does not fail), so removing only `|| true` would not make lint blocking. The `--check` flag is the lint counterpart of `format --check` — it causes a non-zero exit when violations exist.

A pre-existing broken anchor link in `README.md` (`#agentsmd--per-project-ai-behavior`) was also fixed so `panache lint . --quiet --check` passes on the clean tree. The heading `### AGENTS.md --- Per-Project AI Behavior` generates anchor `agents.md----per-project-ai-behavior` in panache's anchor scheme (dots preserved, `---` converted to three hyphens, spaces to hyphens).

## Acceptance Notes

- [x] The CI Docs job runs `panache lint . --quiet --check` without `|| true`
- [x] `panache lint` with `--check` exits non-zero when violations exist (verified with a test file containing `[broken ref]`)
- [x] `panache lint . --quiet --check` passes on the current tree (exit 0)
- [x] A pre-existing broken anchor link in README.md was fixed so the lint passes
