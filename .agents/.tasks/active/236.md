# Replace Duplicate-Mutation Guard with Per-Path Serialization

**Created:** 2026-07-07
**Source:** 2026-07-07 backlog triage (bitter-lesson audit V2 / Phase 2 item 7).

## Problem

Tool calls in one assistant turn run concurrently via `join_all`. Rather than fix the resulting same-file race, the harness rejects the second same-file Edit/Write (`src/clients/tools/duplicate_guard.rs`, ~394 lines) and burns an API round-trip telling the model to re-read. The workaround is then echoed in three prompt layers: `src/prompts/system.md` ("Do not issue multiple Edit or Write calls for the same file in one turn"), `edit-description.txt`, and `write-description.txt` — four encodings of one implementation shortcut, and a model that correctly batches two sequential edits to one file gets punished.

Decision (2026-07-07): fix the race with per-path serialization. This is deliberately narrower than cancelled task 202 (which proposed serializing all tool calls, including Bash, and was rejected as over-complicated): serializing only same-path mutations fixes the harness's own concurrency choice without constraining model judgment.

## Fix Direction

- In the agent loop scheduling (`src/clients/agent/agent_loop.rs`), group scheduled mutating calls by canonical target path (the existing `mutating_target` extraction). Groups run concurrently with each other and with non-mutating calls; members within a group run sequentially in issue order, each seeing the previous call's effects.
- Delete the rejection path in `duplicate_guard.rs`; keep/relocate only the canonical-path extraction the scheduler needs.
- Delete the three prompt-layer echoes (system.md line, edit-description.txt, write-description.txt). Note: task 164 added some of this guidance; it is intentionally reverted by this change.
- Tool results must preserve per-call attribution and ordering in session records and stream-json output.
- This changes tool execution semantics — a documented compatibility surface. Update `docs/design-docs/tools.md` and `docs/guardrails/agent-loop-tools-and-tool-execution.md`; assess whether an ADR is needed (likely yes, short one, since execution semantics are a durable contract).
- Optionally count serialization events (calls that were reordered/sequenced) in session telemetry so the compensation is measured (see the telemetry-counters task).

## Relevant Files
