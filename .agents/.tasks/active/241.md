# Convert bash_safety Into a Declarative Command-Policy Engine

**Created:** 2026-07-07
**Source:** 2026-07-07 backlog triage (bitter-lesson audit V1 / Phase 2 item 6 — "the big one"). Absorbs the built-in-check portions of task 142 and cancelled task 160.

## Problem

`src/clients/tools/bash_safety/` (~2,300 lines: mod + checks + parse) is hand-enumerated compiled judgment. Nine hard-block rules encode git-workflow opinions (`git reset --hard`, `checkout --`, `restore`, `clean -f`, `push --force`, `branch -D`, `stash drop/clear`, commit-message backticks, `rm -rf`) with **no override mechanism at all** — a user who explicitly asks for a force-push hits a wall the harness put there. Updating any rule requires a release. `parse.rs` is a growing bespoke shell parser (quote tracking, segment splitting, `bash -c` recursion, command-substitution extraction) that will never be correct against real shell semantics and invites endless patching. Tips baked into block messages are workflow lectures frozen at compile time.

The general mechanism already exists in spirit: policy should be data the user owns, enforced by a small engine — with the OS sandbox remaining the actual security boundary.

## Direction

- Ship the current rules as **embedded default policy data** — pattern, severity (block/warn), message — merged with user/project policy files layered the same way settings already layer. Users can relax (`allow` a pattern), tighten, or replace rules without a release.
- Keep the two-tier block/warn severity. Keep the OS sandbox (Seatbelt/Landlock) as the real enforcement boundary; this engine is guidance/policy, not the security wall.
- Shrink `parse.rs` to the minimal matcher the rules need and freeze it — resist ever growing the shell parser again.
- Candidate default policy data to consider once the engine exists (do not pre-implement): the `rg` escaped-alternation warning from task 142; cancelled task 160's broad-`git add` warning fits as *user-level* policy, not a shipped default.
- Record per-rule fire counts in session telemetry (see the compensation-counters task) so rules have measurable relevance.

## Prerequisites

This is a one-way ownership decision (compiled beliefs → user-owned data) touching a security-adjacent surface:

- **ADR required before implementation** (policy file format, layering/merge semantics, override rules, security posture).
- **ExecPlan required** (Effort L).
- Sandboxing route: call out security impact in the handoff. Existing hard-block behavior must be the default-config behavior — no out-of-the-box relaxation.
