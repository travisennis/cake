# Reconcile Git Workflow Docs to Trunk-Based Development

**Created:** 2026-07-07
**Source:** 2026-07-07 harness assessment (feedback finding #4); maintainer decision 2026-07-07: trunk-based development.

## Problem

The doc stack states three different git policies. `CONTRIBUTING.md` mandates "Never commit directly to master — feature branch + PR" and carries "Fork the repository" boilerplate that does not describe this repo. `AGENTS.md` says "Commit on the current branch unless the task or maintainer asks for a branch." Actual history is direct commits to master gated by the prek pre-push hook and GitHub CI. Every agent routed to CONTRIBUTING for verification guidance inherits the contradiction and resolves it randomly.

Decision: trunk-based development is the policy.

## Fix Direction

- Rewrite the CONTRIBUTING.md workflow section to describe the real flow: direct commits to master, prek pre-push gate, GitHub CI as backstop. Delete the fork/PR boilerplate; keep branch+PR only as an optional path for risky/experimental work if worth keeping at all.
- Verify AGENTS.md's repository rules read consistently with that (they largely already do).
- Sweep guardrail docs and any PR-workflow references (`docs/guardrails/dependencies-build-ci-release.md` and CONTRIBUTING cross-references) for the same contradiction.
- Docs-only change; keep the repo agent-agnostic in wording (multiple coding agents work in this repo; cake is primary).

## Relevant Files

- `CONTRIBUTING.md`
- `AGENTS.md`
- `docs/guardrails/dependencies-build-ci-release.md` and any other docs referencing the PR workflow
