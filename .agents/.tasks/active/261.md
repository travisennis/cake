# Fail Required Sandbox Integration Tests When Enforcement Is Unavailable

## Summary

At commit `6e69b45`, cake's macOS sandbox integration tests can return successfully without exercising Seatbelt whenever the current process cannot apply a sandbox profile. This creates false-green verification for security-sensitive sandbox changes: a delegated worker can report that the test suite passed even though the relevant assertions never ran. Add an opt-in required mode that turns inability to enforce the platform sandbox into a test failure while preserving the current convenient skip behavior for ordinary local runs.

## Evidence

- `src/clients/tools/bash_tests.rs:10` — `skip_if_sandbox_unavailable()` prints a skip message and returns `true` when `CAKE_SANDBOX` disables enforcement or `sandbox-exec` cannot apply a profile.
- `src/clients/tools/bash_tests.rs:265` and the other macOS sandbox tests — each test exits early when the helper returns `true`, so Cargo still reports a successful test run.
- `src/clients/tools/sandbox/mod.rs:713` — `can_enforce_platform_sandbox()` already exposes the test-only capability probe needed to distinguish an executed sandbox test from a skipped one.

## Fix Direction

Add a test-only required mode, using a clearly named environment variable such as `CAKE_REQUIRE_SANDBOX_TESTS=1`, that makes the existing skip helper fail with an actionable message when sandbox enforcement is unavailable or explicitly disabled. Default test behavior must remain unchanged so unsupported local and CI environments may still skip. Document one canonical command for security-sensitive sandbox verification and ensure its output makes executed versus skipped enforcement unmistakable. Keep production sandbox policy and runtime fallback behavior out of scope; if a reliable test-only switch cannot be added without changing production semantics, stop and report the coupling before proceeding.

## Acceptance Notes

- [ ] With required mode unset, the existing behavior remains: unsupported environments skip the macOS sandbox integration tests without failing unrelated test runs.
- [ ] With required mode enabled, `CAKE_SANDBOX=off` or an environment where `can_enforce_platform_sandbox()` is false causes the targeted sandbox integration run to fail with an actionable explanation rather than return success.
- [ ] On a macOS host that can enforce Seatbelt, the documented required-mode command executes the sandbox assertions and passes; its recorded output demonstrates that the tests were not skipped.
- [ ] Focused tests cover parsing/selection of required mode and both the default-skip and required-failure branches without weakening existing sandbox assertions in `src/clients/tools/bash_tests.rs`.
- [ ] Contributor or testing documentation names the exact required-mode command to use for sandbox-sensitive changes.
- [ ] `just ci` passes, and the task records the separate required-mode sandbox command and result.
