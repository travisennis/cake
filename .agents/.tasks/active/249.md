# Add Schema-Constrained Final Output

## Problem

Add a non-interactive CLI flag that constrains cake's final response to a JSON document valid against a caller-supplied JSON Schema.

ahm is adding delegation commands such as `ahm task groom` and `ahm audit` that hand procedure prompts to a coding agent and mechanically apply the structured result. cake is ahm's default work agent, so it needs first-class parity with other supported agents that already provide schema-constrained final output. Prompt-only JSON instructions are not reliable enough for this contract.

The schema must constrain only the final response, specifically the `result` field of the `task_complete` stream-json event. Intermediate reasoning, tool use, and multi-turn agent behavior should remain unchanged.

## Proposed CLI Contract

```bash
cake --output-schema <schema.json> --output-format stream-json "<prompt>"
```

- `--output-schema <path>` points to a JSON Schema file describing the final response shape.
- The final response must be exactly the schema-valid JSON document, with no Markdown fences or surrounding prose.
- The run remains fully agentic; only the final assistant result is constrained.
- The flag applies to non-interactive runs and should compose with `--output-format stream-json` and `--resume <session-id>`.
- Prefer native structured-output support from the active backend when available. If native support is not available, a bounded validate-and-retry loop is acceptable as an initial implementation, provided failure is loud and machine-detectable.

## Error Handling

- Unreadable schema file fails before the run starts with a nonzero exit and clear human-readable error.
- Invalid schema file fails before the run starts with a nonzero exit and clear human-readable error.
- A final response that cannot be made schema-valid, including refusal, truncation, or retry exhaustion, must fail with a nonzero exit and/or explicit failure event in the stream.
- Callers must never receive a successful `task_complete.result` that silently contains non-conforming prose.

## Relevant Files

- `src/cli.rs` and related CLI parsing/help modules - add and document the `--output-schema` option.
- `src/agent/` - preserve normal tool-using agent behavior while constraining only final output.
- `src/providers/` or backend-specific request shaping - pass structured-output constraints where supported.
- `src/session/` and stream-json output code - ensure `task_complete.result` contains the JSON document and failure cases are distinguishable.
- `docs/design-docs/cli.md` - document the flag and final-message-only semantics.
- `docs/design-docs/streaming-json-output.md` - document the stream-json result and failure contract if behavior changes.

## Implementation Notes

- This task introduces a user-visible CLI flag and a durable machine-readable output contract. Create an ADR before implementation.
- Effort is large enough to require an ExecPlan before code changes.
- Validate the schema before starting the run.
- Decide whether the supported schema dialect is draft 2020-12 or the subset supported by the active backend, and document that decision.
- Keep compatibility with existing stream-json consumers: additive success behavior is acceptable, but failure signaling must be deliberate and documented.

## Acceptance Notes

- [ ] `cake --output-schema <file> --output-format stream-json "<prompt>"` yields a `task_complete` event whose `result` is a JSON document valid against the schema.
- [ ] The `task_complete.result` has no Markdown fences or surrounding prose.
- [ ] The same behavior works on `--resume <session-id>` runs.
- [ ] Unreadable schema files fail before the run starts with a nonzero exit.
- [ ] Invalid schema files fail before the run starts with a nonzero exit.
- [ ] Refusal, truncation, retry exhaustion, or otherwise unsatisfiable output exits nonzero and/or emits an explicit failure event that stream-json callers can distinguish from success.
- [ ] Help text documents `--output-schema` and its final-message-only semantics.
- [ ] CLI and stream-json design docs are updated for the new contract.
