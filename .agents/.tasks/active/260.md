# Verify linked-worktree Git operations under enforced Seatbelt

## Problem

Task 257 added linked-worktree gitdir and commondir resolution, generated
Seatbelt allow rules, and deterministic profile-generation coverage. The
current execution environment cannot apply Seatbelt profiles, so it could not
prove that `git status`, `git add`, and `git commit` succeed end to end inside
a linked worktree under an actually enforced macOS sandbox.

## Relevant Files

- `src/clients/tools/sandbox/macos.rs` — Seatbelt profile generation and tests.
- `src/clients/tools/bash_tests.rs` — existing enforced-sandbox test patterns.
- `src/clients/tools/sandbox/mod.rs` — linked-worktree metadata resolution.
- Task 257 — implementation and review evidence being followed up.

## Fix Direction

Run or add a macOS-only integration test on a host where
`can_enforce_platform_sandbox()` succeeds. Create a real linked worktree whose
gitdir and common dir are outside the workspace subtree, execute `git status`,
modify and stage a file with `git add`, and create a commit through cake's
enforced Seatbelt execution path. Confirm both externally created and
cake-managed worktrees use the same resolved sandbox configuration; add
separate coverage only if their runtime paths differ.

Do not weaken or bypass Seatbelt to make the test pass. Keep Linux Landlock
coverage out of scope unless shared test infrastructure makes it trivial.

## Acceptance Notes

- [ ] The test host confirms Seatbelt enforcement is active rather than skipped.
- [ ] `git status`, `git add`, and `git commit` succeed in a real linked worktree through the enforced sandbox path.
- [ ] The test verifies the exact per-worktree gitdir and common dir are outside the workspace subtree.
- [ ] Cake-managed and externally created worktree coverage is documented or tested separately if behavior differs.
- [ ] Required focused checks and `just ci` pass.
