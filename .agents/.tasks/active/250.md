# Surface Cut-Off Outcome in JSON Mode Output and Telemetry

**Created:** 2026-07-09
**Source:** 2026-07-09 code review of commit 6acfdd0 (task 243 follow-up).

## Problem

Task 243 added `TaskOutcome::CutOff` so the harness stops fabricating assistant prose, but the conversion in `execute_agent_turn` (`src/main.rs`, around line 747) turns the `CutOffError` into `Ok(detail)` before rendering. Three surfaces still misreport cut-offs as success:

- **JSON mode:** `turn_result_json` (`src/cli/output.rs`, around line 131) puts any `Ok` value into `"result"` with no `"error"` field and exit code 0. A JSON consumer sees `{"result": "The model's response was cut off during reasoning."}` — harness-authored prose in the model-output position, indistinguishable from a real answer. This is the exact problem task 243 set out to fix, relocated to the JSON stdout payload. The session file records `CutOff`, but the JSON payload does not.
- **Telemetry:** `emit_session_summary_telemetry` (`src/main.rs`, around line 968) sees the converted `Ok` and logs `success=true` with no error string, so telemetry cannot distinguish cut-offs from clean completions.
- **Text mode (minor):** the detail prints unattributed in the assistant-output position. Task 243's acceptance note said the explanatory line should be attributed to cake, not rendered as an assistant message.

Stream-json is already correct (emits `task_complete` with `subtype: cut_off`, `is_error: true`; exit 0 matches the documented in-stream-error policy in `src/cli/output.rs`).

## Fix Direction

- Carry the cut-off condition to the render layer as a typed value instead of converting to `Ok(detail)` — e.g. a small enum or the `TaskOutcome` itself on `TurnResult` — so each output mode can render it deliberately.
- JSON mode: emit a distinct shape — the detail in `"error"` with `"result": null`, or an explicit subtype/field. Decide the exit-code contract (probably nonzero to match `"error"`, but weigh against the stream-json precedent of exit 0). This is a documented machine-readable compatibility surface: change must be additive and documented in `docs/design-docs/streaming-json-output.md` / `docs/design-docs/cli.md` as appropriate.
- Telemetry: report `success=false` (or a distinct outcome) with the detail for cut-off turns.
- Text mode: prefix or otherwise attribute the explanatory line to cake.

## Relevant Files

- `src/main.rs` — `execute_agent_turn` render-result conversion, `emit_session_summary_telemetry` call site
- `src/cli/output.rs` — `turn_result_json`, `render_text_result`, exit-code policy
- `src/cli/` — `TurnResult` shape
- `docs/design-docs/streaming-json-output.md`, `docs/design-docs/cli.md` — compatibility documentation

## Acceptance Notes

- [ ] JSON mode output for a cut-off turn is distinguishable from a successful result (no harness prose in `"result"`).
- [ ] Exit-code behavior for cut-offs is decided per mode and documented.
- [ ] Session telemetry records cut-off turns as not-success with the detail.
- [ ] Text mode attributes the explanatory line to cake.
- [ ] Existing JSON consumers of successful turns are unaffected (additive change).
- [ ] Tests cover the cut-off path in json, text, and telemetry surfaces.
