# Configure Independent Higher-Reasoning Review for Cake Task Work

## Summary

At commit `6e69b45`, cake's `.agents/ahm.json` does not configure `taskWork.implementation` or `taskWork.review`, so `ahm task work` uses the same default cake agent/model for implementation and independent review. In task 260, both phases used `deepseek-v4-flash`; the reviewer repeated the implementation's mistaken conclusions about a broadly writable fixture and skipped Seatbelt enforcement. Dogfood ahm's existing role-specific configuration with a deliberately independent, higher-reasoning review path for this repository.

## Evidence

- `.agents/ahm.json:1-9` — project metadata contains version, acceptance policy, and managed skill hashes but no `taskWork.review` role.
- Ahm completed task 167 documents the supported `taskWork.implementation` and `taskWork.review` agent/model configuration and its precedence; no ahm feature work is required.
- Cake worker session `3954579a-afc0-4c5c-a497-4cbbd33047a1` and review session `b09b6303-8ba2-45c3-b543-9a8757e33d78` both used `deepseek-v4-flash`, producing correlated acceptance errors on task 260.

## Fix Direction

Select and configure an available review agent/model with materially stronger reasoning than the routine implementation default, using the existing `taskWork.review` block in `.agents/ahm.json`. Prefer a different model family or agent surface where practical to reduce correlated mistakes, and record the reliability/cost rationale in durable project workflow documentation. Keep provider credentials and user-specific paths out of repository metadata; if no suitable team-available model name can be committed portably, stop and propose a documented user-local configuration contract instead of committing a broken default.

## Acceptance Notes

- [ ] `.agents/ahm.json` configures a supported `taskWork.review` agent/model while preserving existing metadata fields and generated skill hashes.
- [ ] The selected reviewer is materially more capable than the routine implementation default and, where practical, independent by model family or agent surface; the rationale and expected cost trade-off are documented.
- [ ] `ahm --dry-run task work <safe fixture task>` reports distinct resolved implementation and review roles/models without modifying the fixture task.
- [ ] A controlled review smoke test uses a deliberately flawed, non-production fixture containing contradictory or skipped verification evidence, and the configured reviewer reports the flaw.
- [ ] Repository configuration contains no API keys, credentials, absolute user paths, or assumptions that make task work unusable for another contributor; any required local setup is documented.
- [ ] Existing cake verification remains unchanged and `just ci` passes if documentation or checked configuration validation touches code-adjacent tooling.
