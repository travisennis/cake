# Cut-Off Detection Is Masked on All But the First Turn

**Created:** 2026-07-09
**Source:** 2026-07-09 code review of commit 6acfdd0 (pre-existing edge, not a regression from task 243).

## Problem

`resolve_assistant_message` (`src/clients/agent_state.rs`, around line 117) returns the last assistant message found anywhere in conversation history. In a resumed or multi-turn session, history already contains assistant messages from earlier turns, so when the current turn is cut off (no new assistant message produced), the function returns the *previous* turn's final message instead of `None`. The `TaskOutcome::CutOff` path added by task 243 therefore only fires on the first turn of a fresh session; later-turn cut-offs silently report the stale prior answer as the current result.

Relatedly, the `cut_off_error` heuristic (`src/clients/agent/agent_loop.rs`, around line 578) scans all of history for `Reasoning` items, so reasoning from an earlier turn can mislabel a fresh empty response as "cut off during reasoning."

## Fix Direction

- Scope assistant-message resolution to the current turn — e.g. track the history index at turn start (or the last user message position) and only consider items after it, both in `resolve_assistant_message` and in the `cut_off_error` detail heuristic.
- Verify against continue/resume/fork flows: session compatibility surfaces must be preserved; this changes detection only, not record shapes.

## Relevant Files

- `src/clients/agent_state.rs` — `resolve_assistant_message`, `ConversationState` history tracking
- `src/clients/agent/agent_loop.rs` — `cut_off_error`, turn boundaries
- `docs/design-docs/conversation-types.md` — if turn-boundary semantics are documented

## Acceptance Notes

- [ ] A cut-off on turn N of a multi-turn session produces `TaskOutcome::CutOff`, not turn N-1's message.
- [ ] Resumed (`--continue`/`--resume`/fork) sessions detect cut-offs on their first new turn.
- [ ] `cut_off_error` detail reflects only the current turn's items.
- [ ] Unit tests cover multi-turn and resumed-history cut-off scenarios.
