# Graceful Fallback When Nested Inside Another Seatbelt Sandbox

## Problem

cake uses `sandbox-exec` (macOS Seatbelt) to sandbox every Bash tool invocation. When cake itself is already running inside another Seatbelt sandbox (e.g. inside OpenAI Codex CLI, Claude Code, or any other tool that uses `sandbox-exec`), macOS rejects the nested `sandbox_apply` syscall with EPERM. Currently, `detect_macos_platform()` treats any sandbox probe failure as a hard error and blocks all Bash commands. This prevents cake from functioning as a subagent inside any other sandboxed AI coding assistant.

## Relevant Files

- `src/clients/tools/sandbox/mod.rs` — `detect_macos_platform()` at lines 714-742 returns `Err` when profile can't be applied.
- `src/clients/tools/sandbox/macos.rs` — `probe_can_apply_profile()` at line 46 runs the sandbox-exec probe; `can_apply_profile()` caches and returns the result.
- `src/clients/tools/bash.rs` — `execute_bash_with_args()` at line 334 propagates the `Err` via `?`.

## Fix Direction

In `detect_macos_platform()`, distinguish the nested-sandbox case (stderr contains `sandbox_apply: Operation not permitted`) from other probe failures. When the probe fails specifically because we're already inside another sandbox, return `Ok(None)` with a `tracing::warn!` instead of returning `Err`. This allows the Bash tool to run commands unsandboxed — the outer sandbox already constrains the process tree, so cake's sandbox would be redundant.

The outer sandbox still protects the host, so there is no reduction in real security.

## Acceptance Notes

- [ ] `detect_macos_platform()` returns `Ok(None)` when the probe failure message contains `sandbox_apply: Operation not permitted`.
- [ ] Other probe failures (missing `sandbox-exec`, broken profile, etc.) still return `Err` and block execution.
- [ ] A `tracing::warn!` message is emitted when falling back to unsandboxed execution.
- [ ] `codex exec` can run through cake's Bash tool without `--sandbox danger-full-access` when cake is nested inside another sandbox.
- [ ] `claude` or any other Seatbelt-using tool also benefits automatically.
- [ ] Test: mock a nested-sandbox probe failure → expect `Ok(None)` and a warning log.
- [ ] Test: mock a non-nested probe failure → expect `Err`.
