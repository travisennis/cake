# Support linked git worktrees in the sandbox profile

## Summary

When cake's workspace is a linked git worktree (created with `git worktree
add`), the workspace `.git` is a file whose `gitdir:` pointer targets
`<parent>/.git/worktrees/<name>`, and git also needs the common dir
`<parent>/.git` (objects, refs, config; the per-worktree dir holds index,
HEAD, MERGE_MSG). The sandbox profile only allows the workspace subtree plus
home-level git config (`append_git_rules` in
`src/clients/tools/sandbox/macos.rs`), so every git command inside a linked
worktree fails with `fatal: ... Operation not permitted`.

Observed 2026-07-12 running `ahm task work` inside a linked worktree of the
ahm repository (cake session 4988adce): implementation and review phases
succeeded, but the commit handoff could not run any git command and had to
hand back manual commands. The failure surfaced only at the end of a long
run, at the first git invocation.

## Relevant Files

- src/clients/tools/sandbox/macos.rs (profile construction, `append_git_rules`)
- src/clients/tools/sandbox/mod.rs (path allowlist assembly)
- src/config/worktree.rs (cake-managed worktrees; external worktrees take a different path)

## Fix Direction

At sandbox profile construction, detect that `<workspace>/.git` is a file,
parse its `gitdir:` pointer, resolve the target directory and the
`commondir` file inside it, and add read/write rules for both the
per-worktree gitdir and the common git dir. Cover cake-managed worktrees and
externally created ones. If the gitdir cannot be granted, report it at
session start rather than failing at the first git call late in a run.

## Acceptance Notes

- [ ] A session launched inside a linked worktree can run git status/add/commit under the sandbox
- [ ] Both the per-worktree gitdir and the common dir are resolved from the .git file, not assumed
- [ ] When the gitdir cannot be sandboxed, cake warns at session start
- [ ] Regression test covers a linked-worktree workspace
