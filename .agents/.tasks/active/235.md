# Delete Skill-Read Interception and Dedup; Keep the Read Tool

**Created:** 2026-07-07
**Source:** 2026-07-07 backlog triage (bitter-lesson audit V3 / Phase 2 item 8); supersedes cancelled tasks 158 and 223.

## Problem

The `Read` tool intercepts known `SKILL.md` paths: re-reading an active skill returns "already active in this session" instead of file contents, backed by a pending/active/reserved state machine (`src/clients/skill_dedup.rs`, ~170 lines plus `Agent` plumbing and resume pre-seeding).

This withholds an information-access decision from the model. Session `5985a540-c632-4563-a5da-c9bbe54f866d` shows the cost: the dedupe message blocked legitimate inspection of changed skill files during a review, the agent fell back to Bash `sed`, and hooks blocked that too. The claimed savings is occasionally not re-reading a 1–2KB file; the claim "its instructions are already in the conversation context" becomes false the moment any future context trimming exists (task 208).

Decision (2026-07-07): keep `Read` as a built-in tool (full removal per task 223 rejected — it is the highest-volume tool, line numbers anchor Edit workflows, and hooks steer agents toward it). Delete the interception and dedup.

## Keep

- Skill discovery and catalog prompt disclosure.
- `SkillActivated` session records: emit by path-watching Read calls that target known `SKILL.md` paths — record the activation, do not substitute the output.
- Loading and resuming old sessions containing historical `skill_activated` records.

## Relevant Files

- `src/clients/skill_dedup.rs` — delete
- `src/clients/agent.rs`, `src/clients/agent/agent_loop.rs` — `execute_tool_with_skill_dedup` and activation state plumbing
- `src/clients/tools/read.rs` — no skill-specific behavior remains
- `src/config/session.rs` — resume pre-seeding of activated skills
- `src/types/session.rs` — `SkillActivated` record (retained)
- `docs/adr/002-agent-skills.md` — records Read-based dedup as accepted; amend or supersede the dedup portion
- `docs/design-docs/skills.md`, `docs/design-docs/tools.md`
- Skill dedup/activation tests

## Fix Direction

1. Write the ADR amendment/supersession for ADR-002's dedup decision first (durable change to skill activation behavior).
2. A `Read` of a `SKILL.md` always returns file contents like any other read.
3. Path-watch reads of known skill paths to emit `SkillActivated` once per session per skill (subsequent reads read normally, no new record needed).
4. Delete the state machine, reservation logic, and resume pre-seeding that exists only to suppress re-reads.
5. Open question to settle in the ADR: whether a first read of a known `SKILL.md` should default to the whole file instead of the 200-line window (evidence from cancelled task 158: long skills can be silently truncated at activation). Prefer the simplest answer that avoids reintroducing special cases; catalog instructions can tell the model to read the full file.
