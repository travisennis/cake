# Local Gate Prerequisites

Use this runbook when a local gate cannot run because of the machine rather than the change: a missing tool, an unaccepted toolchain license, a missing Rust target, or a missing provider credential. The goal is to name the prerequisite, restore it when that is safe, and record what could not be checked, so a handoff never turns a prerequisite failure into an unqualified "checks passed".

[CONTRIBUTING § Verification](../../CONTRIBUTING.md#verification) owns the change-class matrix and the reporting rule; this runbook owns the diagnosis and recovery.

## Step 1: Separate a prerequisite failure from a source failure

- A prerequisite failure appears before the crate compiles, or in the linker or tool banner, and names a tool, license, target, or credential instead of a source path. A source failure names files and lines under `src/` or `tests/`, and repeats after a clean rebuild.
- Reproduce it outside the change: run the raw command in a scratch directory (`printf 'int main(void){return 0;}\n' > /tmp/probe.c && cc /tmp/probe.c -o /tmp/probe`). If that fails the same way, the machine is at fault, not the diff.
- Before calling a failing check unrelated to the change, check whether the same signature already occurs on `master`. A moved base, a stale cache, and a genuinely pre-existing failure look alike from one branch.

## Step 3: Fall back to the checks that still run

Several gates need no compiled artefact, no coverage pass, and no network. When a prerequisite blocks the Rust gate, these still produce evidence:

- `just cc-check` --- the per-function complexity ratchet (source scan, about a tenth of a second).
- `just check-scripts` --- the Python fixture suites, including the coverage artifact guard.
- `just docs-check` --- Markdown formatting and lint over the corpus.
- `just pre-push-classify` --- the change class the routed gate would use.
- The focused commands for the surface being changed, such as `cargo test <name>` where the toolchain does work, or `python3 scripts/session-metrics/report.py --days 1` for metrics.

## Step 4: Report it

State the exact command, the exact error line, and the narrower checks that did run, and hand the recovery command to the operator when it needs privileges the agent lacks. Do not report a gate as passed when it never reached the crate, and do not silently drop a gate from the list: an unrun gate belongs in the handoff and in the pull request with its reason.
