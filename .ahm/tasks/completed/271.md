# Minimize post-fork work in Linux Landlock setup

## Summary

At commit `6e69b45`, Linux Landlock rule construction occurs inside `Command::pre_exec`, after fork in Tokio's multithreaded process. The closure performs heap allocation, formatting, path existence checks, and vector construction; non-async-signal-safe work in this phase can deadlock the child before `exec`, producing rare unrecoverable command hangs.

## Evidence

- `src/clients/tools/sandbox/linux.rs:34-42` — `LandlockSandbox::apply` clones config and registers a `pre_exec` closure.
- `src/clients/tools/sandbox/linux.rs:45-118` — the closure calls `apply_landlock_rules`, which constructs access sets, formats error strings, checks `path.exists()`, builds vectors, and applies the ruleset.
- The unsafe block's safety comment explains why Landlock must be applied pre-exec but does not make the allocation-heavy preparation async-signal-safe.
- This is Linux-only and timing-sensitive; the risk is a known post-fork hazard rather than an easily deterministic functional failure.

## Fix Direction

Move all preparation that can safely occur before fork—path filtering, owned rule data construction, and error-context assembly—out of `pre_exec`, leaving only the minimal Landlock syscalls/state transition required in the child. Preserve fail-closed behavior for missing or partial enforcement and preserve workspace/read-only policy semantics. Do not relax Landlock access rights to simplify the lifecycle. If the Landlock crate API fundamentally requires allocation inside `pre_exec`, stop and document upstream/API options before introducing a custom unsafe implementation.

## Acceptance Notes

- [x] The `pre_exec` closure now only takes the inherited prepared ruleset,
  invokes Landlock's `no_new_privs`/`restrict_self` path, maps failures to an
  errno-backed `io::Error`, checks the enforcement status, and closes the
  ruleset FD.
- [x] Path existence filtering, owned ruleset construction, rule-FD lookup,
  rule insertion, allocation, and error formatting all occur before

- [x] Full enforcement succeeds while partial and unavailable enforcement

  Landlock is an unconditional Linux target dependency, not a Cargo feature.
- [x] `just ci` passes.

## Security Impact

The change defends against child execution without a fully enforced ruleset,
partial ABI enforcement, omission or misclassification of configured allowed
paths, and post-fork deadlock caused by allocation, formatting, filesystem
discovery, or process-global locks. It does not widen any access right or alter
workspace-write/read-only path classification. Missing paths remain omitted
before rule construction, and every incomplete enforcement result still stops
the spawn.
