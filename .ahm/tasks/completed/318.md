# Redact the API key from `ResolvedModelConfig`'s `Debug` output

## Summary

At commit `e569256`, `ResolvedModelConfig` derives `Debug` while holding the resolved API key as a plaintext `String`. No current call site formats it, so this is latent rather than a live leak — but the type is threaded through code where debug logging is routine, and a single `?config` in a future debugging session would write the key to the log file.

## Problem

`complete_turn` passes `&ResolvedModelConfig` through the retry loop, which is exactly where someone reaches for `tracing::debug!` or `trace!` on request context while diagnosing a provider issue. The derived `Debug` makes that mistake silent: it compiles, it looks like normal instrumentation, and the credential ends up in a log file that may be shared in a bug report.

A manual `Debug` implementation that redacts the field removes the failure mode entirely and costs one small impl.

## Evidence

- `src/config/model.rs:112-119` — `#[derive(Debug, Clone)] pub struct ResolvedModelConfig` with `pub api_key: String`.
- `src/clients/retry.rs` — the retry path receives `&ResolvedModelConfig`; surrounding code logs request context.
- Verified at this commit: no call site currently formats the struct with `Debug`, so nothing leaks today.

## Fix Direction

Replace the derived `Debug` with a manual implementation that prints the `model_config` normally and the key as a fixed redaction marker. Do not print a prefix, suffix, or length of the key — those leak useful information and invite the "just a few characters" argument later.

Consider whether the same treatment belongs on any other type that carries the resolved key or on `ModelConfig` if it ever holds secret material; if so, cover them here rather than filing a follow-up. Do not change the field's visibility, the resolution logic, or how the key reaches the provider — this is about formatting only.
