# Enforce Feature-Branch Development and Support Parallel Worktrees

## Context

Cake is developed by committing directly to `master`. Agents are told to do the
same: `AGENTS.md` Repository rules say "Work on the current branch unless asked
to create another", and `CONTRIBUTING.md` Git and commits says "Branches are
optional unless the work or maintainer requires one". Nothing mechanical
prevents a commit or push to `master`: `gh api repos/travisennis/cake/branches/master/protection`
returns 404 (branch not protected), and `prek.toml` has no branch guard.

The maintainer wants branch-per-task development with pull requests, and wants
multiple agents working in parallel git worktrees. This task establishes the
mechanism.

Relevant existing state:

- `cake --worktree [NAME]` already exists (`src/main.rs` `worktree` flag,
  `src/config/worktree.rs` `create`). It builds `<repo>/.cake/worktrees/<name>`
  on branch `worktree-<name>` from the default remote branch and copies files
  matching a repo-root `.worktreeinclude`.
- `.gitignore` ignores `.acai/worktrees/` but not `.cake/worktrees/`, so cake's
  own worktrees appear as untracked content in the parent working tree.
- No `.worktreeinclude` exists at the repo root, so new worktrees come up
  missing untracked local files such as `.local.justfile` and
  `.claude/settings.local.json`.
- `.github/workflows/ci.yml` already runs on `pull_request` against
  `master`/`main`. Its `coverage` job is conditional
  (`if: github.event_name == 'push' || needs.changes.outputs.coverage == 'true'`),
  so it must not be a required status check: a skipped required check blocks a
  PR permanently.
- `CODEOWNERS` assigns every path to `@travisennis`. Required approvals must be
  0, because a solo maintainer cannot approve their own pull request.
- `.ahm/.gitignore` ignores generated `index.md` files, so parallel branches do
  not conflict on task indexes. `ci/cargo-crap-baseline.json` is tracked and
  generated, so it does conflict.
- Each git worktree gets its own cold `target/`, which is expensive for this
  dependency set. A shared `CARGO_TARGET_DIR` is the wrong fix because cargo
  takes an exclusive lock on it and parallel builds would serialize.

## Work

1. Ignore `.cake/worktrees/` and add a repo-root `.worktreeinclude` covering
   the untracked local files a worktree needs.
2. Add a `prek` pre-commit hook that refuses commits on `master`.
3. Add `sccache` to the shared build path (`just setup`, `.cargo/config.toml`)
   so parallel worktrees share compilation results without contending on a lock.
4. Rewrite the branch guidance in `AGENTS.md` and `CONTRIBUTING.md` to require
   a branch per task, created from an up-to-date `master` at task start, and a
   pull request for integration.
5. Add `docs/runbooks/parallel-worktrees.md` covering the branch, worktree, and
   pull-request mechanics, and route to it from `AGENTS.md`.
6. Document the `ci/cargo-crap-baseline.json` conflict policy: never
   three-way-merge it; take `master`'s copy and regenerate.
7. Apply a GitHub ruleset on `master`: require a pull request, require the
   non-conditional CI checks, require linear history, no bypass actors.

Deliberately out of scope: lightening the `just pre-push` gate for
feature-branch work, which is task 279; and cross-worktree task claiming, which
the maintainer will handle manually for now.

## Verification

Items 4 and 5 are behavior-shaping instruction changes under
`docs/guardrails/agent-instructions.md`.

- Motivating failure: none observed in a session. The instructions are being
  changed by maintainer directive, because the current instructions actively
  tell an agent to stay on the current branch, which contradicts the intended
  workflow.
- Expected behavior change: an agent starting managed work creates a branch off
  an up-to-date `master` before its first edit, and hands off a pushed branch
  and pull request rather than a dirty working tree on `master`.
- Probe: deferred. The probe that would establish it is a fresh agent session
  given a small task from the ready queue, checked with the
  `analyzing-cake-sessions` skill for whether the branch rule was retrieved and
  a branch was actually created before the first edit.

Mechanical verification for the rest: `git check-ignore .cake/worktrees`
succeeds; a commit attempt on `master` is rejected by the pre-commit hook; a
direct push to `master` is rejected by the ruleset; `panache format --check`
and `panache lint` pass on changed documents; `ahm doctor` passes.

## Acceptance criteria

- Committing on `master` fails locally and pushing to `master` fails remotely,
  with no bypass actor configured.
- `AGENTS.md` and `CONTRIBUTING.md` agree that work happens on a branch, with
  no remaining "branches are optional" statement.
- A cake worktree can be created and built without polluting the parent working
  tree and without a full cold rebuild of the dependency graph.
- The generated-file conflict policy for `ci/cargo-crap-baseline.json` is
  documented in one authoritative place.
