# Fix short-read in Read tool binary detection

## Summary

At commit `e569256`, `is_binary` performs a single `read()` call and treats however many bytes it happens to return as the whole 8 KiB probe window. A short read causes null bytes later in that window to be missed, so a binary file can be admitted to the UTF-8 read path.

## Problem

`std::io::Read::read` is permitted to return fewer bytes than the buffer size. Regular files on local filesystems normally fill the buffer, but FIFOs, files on network mounts, and files served through FUSE can legitimately return a short read. When that happens, `is_binary` inspects only the returned prefix, returns `false`, and `read_file` proceeds to decode the file as UTF-8 and emit it into the model's context.

## Evidence

- `src/clients/tools/read.rs:91-100` — `(&file).take(8192).read(&mut buf)` uses the single-call `read`, and `buf[..n]` is the only region checked.
- `src/clients/tools/read.rs:108-114` — `read_file` gates the entire UTF-8 path on that one result.

## Fix Direction

Read the full probe window before deciding: `read_to_end` on the `Take`, or `read_exact` with `ErrorKind::UnexpectedEof` tolerated for files shorter than the window. Keep the 8 KiB window, the null-byte criterion, and the existing error message shape — this is a correctness fix, not a change to the detection heuristic or to the model-visible error text.

## Acceptance Notes

- [x] Binary detection inspects the full available probe window (up to 8 KiB) regardless of how the underlying reader chunks its returns.
- [x] A test covers a reader that returns fewer bytes than requested on the first call with a null byte beyond that prefix, and fails against the current implementation.
- [x] Files shorter than the probe window still work, and the existing binary-file rejection message is unchanged.
- [x] `cargo test read` and `just ci` pass.
