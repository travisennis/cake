# Include parse-failure context in Edit invalid-argument errors

## Problem

When Edit tool arguments fail JSON parsing, the model receives serde's raw message plus a generic expected-shape line, e.g.:

```
Error: Invalid edit arguments: control character (\u0000-\u001F) found while parsing a string at line 1 column 99
Expected shape: {"path":"file.txt","edits":[{"old_text":"...","new_text":"..."}]}
```

Tool-call argument payloads are single-line blobs that are frequently several KB (observed failed-call median 1,250 bytes, max 7,273 bytes), so "line 1 column 99" gives the model nothing actionable, and the expected-shape hint addresses structure the model usually already got right. Session analysis over 30 days shows ~60 invalid-argument failures; they recover via blind retry most of the time, but slowly — better feedback should make retries converge on the first attempt.

## Relevant Files

- `src/clients/tools/edit.rs` — `parse_edit_args` builds the current error message.
- `src/clients/tools/write.rs` — same pattern for Write arguments; apply the same improvement.
- `src/clients/tools/edit_tests.rs` — tests for the new error format.

## Fix Direction

When strict parsing fails (after any lossless repair pass, if task for argument repair lands first):

1. Extract the byte offset of the failure from the serde error (line/column → offset against the raw payload).
2. Echo a bounded context window (~80 chars around the offset) of the raw payload in the error, with a caret or marker at the failure position. Escape control characters visibly (e.g., show a raw tab as `\t`) so the problem is legible.
3. Add a targeted hint keyed off the error kind:
   - control character in string → "raw tab/newline inside a JSON string — escape it as \\t / \\n"
   - trailing characters → "content continued after the closing brace of the arguments object"
   - missing field `path` → "the path field was never provided; emit path before the edits array"
4. Keep the message bounded (cap context length; never echo the full payload).

This is an error-message change only; no change to what payloads are accepted.
