# Terminate timed-out hook processes

## Summary

At commit `6e69b45`, a timed-out command hook is dropped without any kill-on-drop policy or explicit termination. The hook returns a timeout outcome while the underlying shell process can continue running, allowing repeated slow hooks to accumulate orphaned work.

## Evidence

- `src/hooks.rs:609-614` — `shell_command` configures piped stdio but does not enable `kill_on_drop` or process-group cleanup.
- `src/hooks.rs:616-629` — the spawned `Child` is owned by `run_command_hook`.
- `src/hooks.rs:648-674` — `timeout(command.timeout, child.wait_with_output())` consumes the child; the timeout branch returns immediately without explicitly killing and reaping the process.

## Fix Direction

Ensure hook timeout and early-error paths terminate and reap the hook command, including descendants where supported by the existing process model. Preserve hook decision parsing, timeout error wording, event records, and configured timeout semantics. Keep this separate from Bash tool lifecycle work because hook execution has its own transcript and decision contracts. If descendant cleanup cannot be made portable without changing hook command semantics, stop and report the platform tradeoff.
