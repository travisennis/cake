# Recover reasoning-only and incomplete model turns in place

**Source:** Investigation of sessions `63e582e4-f65a-4d02-8bff-3f25f8c7d454`
and `f5a7ddf3-ff1d-4de3-8abf-3453caaaeee9` on 2026-07-29.

## Problem

When a successful provider response contains reasoning or other partial state
but no final assistant message, `Agent::send` immediately returns
`CutOffError`. Cake emits terminal `task_complete/cut_off` and ends the
invocation without attempting recovery. A later bare prompt defaults to a new
session, so the user's `try again` created `f5a7ddf3` without the context from
`63e582e4`.

The session was persisted and explicit `--resume` was available, but Cake
should first attempt bounded recovery inside the failing invocation. This keeps
the original session and task identities, avoids making the user know recovery
flags, and prevents duplicated investigation and tool work in a fresh session.

## Scope and Direction

- Add one automatic continuation attempt when a provider turn has no final
  assistant message and its termination metadata does not identify a
  non-retryable condition such as content filtering or refusal.
- Keep the same session ID and task ID; do not create a second session or emit
  an intermediate `task_complete`.
- Preserve accumulated usage, turn counts, tool-call counts, streamed records,
  and conversation history across the recovery attempt.
- Supply explicit model-visible continuation context that asks for the missing
  final answer while avoiding blind re-execution of already completed tools.
- Handle trailing, unpaired reasoning correctly for both Chat Completions and
  Responses API request shaping. Do not rely on provider-specific reasoning
  being replayable as an ordinary assistant message.
- Emit retry telemetry and progress using a distinct semantic-incomplete retry
  reason.
- If recovery also ends without a final assistant message, emit the existing
  terminal `TaskOutcome::CutOff` exactly once.
- Preserve the existing rule that a bare invocation starts a new session;
  recovery belongs inside the original invocation rather than changing global
  CLI session-selection semantics.
- Improve the exhausted-recovery diagnostic to include the exact
  `cake --resume <UUID> "try again"` command.

## Compatibility and Risk

This changes provider request count, turn count, streamed event ordering, final
latency, and when stop/error hooks run. The implementation must analyze those
surfaces explicitly and must not invoke the Stop hook until recovery succeeds
or is exhausted.
