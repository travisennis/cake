# Exclude Edit/Write tools from the registry under --sandbox read-only

## Problem

`--sandbox read-only` (ADR-014, task 195) only constrains Bash execution. The default tool registry (`src/clients/tools/mod.rs` `default_tool_registry`) always registers Edit and Write, which mutate files in-process with no sandbox and no policy check. Under `cake -s read-only`, the model can still rewrite any workspace file via Edit/Write.

ADR-014 describes read-only as suitable "for auditing, untrusted prompts, or defensive runs" and says it "denies all mutations to the workspace"; the README table says "Most restrictive: … no writes to workspace." Both overstate what shipped. This is a security-semantics gap in a feature users will rely on for untrusted input.

## Decision (maintainer, 2026-07-09)

Under `SandboxPolicy::ReadOnly`, do not load Edit and Write into the tool registry at all (rather than registering them and returning a policy-denied error). The model never sees tools it cannot use, so it will not burn turns attempting writes, and the advertised tool list truthfully reflects session capabilities.

## Fix Direction

- Build the tool registry from the resolved policy: `ReadOnly` → Bash + Read only; `WorkspaceWrite` / `DangerFullAccess` → unchanged full set.
- `Agent::new` currently hardcodes `default_tool_registry()`; thread the policy (or a registry) from the CLI/session-factory path the same way `ToolContext` is threaded (`src/cli/session_factory.rs`).
- Verify the system prompt / tool-list section (`format_tool_list_section`) reflects the reduced set.
- Amend ADR-014 (More Information / Consequences) and the README + `docs/design-docs/sandbox.md` policy tables to state that read-only also removes the Edit/Write tools.
- Compatibility surfaces: tool execution semantics and prompts change only for the new `read-only` policy; default behavior must remain byte-identical.

## Relevant Files

- `src/clients/tools/mod.rs` (`default_tool_registry`)
- `src/clients/agent.rs` (`Agent::new`, `with_tools` is currently test-only)
- `src/cli/session_factory.rs`, `src/main.rs` (threading)
- `docs/adr/014-sandbox-policy-cli-flag.md`, `README.md`, `docs/design-docs/sandbox.md`

## Acceptance Notes

- Unit test: registry built for `ReadOnly` contains exactly Bash and Read; `WorkspaceWrite` registry unchanged.
- Test: agent constructed via the session factory with `ReadOnly` advertises no Edit/Write in `tool_names()`.
- Docs and ADR-014 updated; default-policy behavior demonstrably unchanged.
