# Fix the launchd SSH agent socket regex in the macOS sandbox profile

## Summary

At commit `c0b7faa`, the Seatbelt rule intended to allow the launchd-managed SSH agent socket uses the pattern `^/private/tmp/com\.apple\.launchd\.*/Listeners`. In regex semantics `\.*` means "zero or more literal dots", so real socket paths like `/private/tmp/com.apple.launchd.AbCdEf12/Listeners` do not match (the random suffix after the dot cannot be consumed). The rule as written matches essentially nothing. The bug is masked when `SSH_AUTH_SOCK` is set, because a separate rule allows that socket's parent directory.

## Evidence

- `src/clients/tools/sandbox/macos.rs:162-165` — the rule emits `\\.*` (escaped dot + star) where the intent is `\\..*` or an equivalent that matches the random launchd suffix.
- `src/clients/tools/sandbox/macos.rs:169-174` — the `SSH_AUTH_SOCK` parent-dir rule that masks the failure in most environments.

## Fix Direction

Correct the pattern (e.g. `^/private/tmp/com\.apple\.launchd\..*/Listeners$` or a subpath-style match) and add a unit test asserting the generated profile contains a rule that matches a representative launchd socket path. Keep the existing `/tmp/ssh-` and `SSH_AUTH_SOCK` rules.
