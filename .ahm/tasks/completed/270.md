# Bound .worktreeinclude traversal and glob matching

## Summary

At commit `6e69b45`, `.worktreeinclude` processing recursively visits nearly the entire source repository and applies every pattern to every file. Large ignored trees such as `target/` and `node_modules/` are not pruned, and the hand-written recursive matcher can explore exponentially many branches for patterns containing multiple wildcards.

## Evidence

- `src/config/worktree.rs:293-315` — recursive traversal skips only `.git` and `.cake`; all other directories are descended before any pattern-based pruning.
- `src/config/worktree.rs:323-325` — every encountered file is tested against every configured pattern.
- `src/config/worktree.rs:354-390` — `**` and `*` recursively retry the remaining pattern at every possible byte position without memoization, creating backtracking blowups for adversarial or simply complex wildcard patterns.
- `src/config/worktree.rs:508-576` — matcher tests cover correctness but not complexity or bounded behavior.

## Fix Direction

Avoid scanning known heavy irrelevant trees and replace or bound the recursive matcher with a linear/polynomial implementation or a maintained glob walker that can prune traversal from the patterns. Preserve the documented `.worktreeinclude` syntax and copying of gitignored files at arbitrary depths. Do not update dependencies unless the maintainer explicitly approves one; first evaluate an in-tree iterative/memoized solution and Git-aware enumeration. If pruning a directory could suppress an explicitly included path such as `target/specific-file`, define and test precedence rather than silently changing semantics.
