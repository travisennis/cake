# Bound the AGENTS.md review loop and require escalation on security-boundary work

**Source:** Multi-session analysis 2026-07-27 (143 sessions, 2026-07-13 .. 2026-07-27).

## Problem

AGENTS.md operating loop step 8 reads:

> After implementation edits, run a review in a subagent until no actionable findings remain, then perform preflight.

"until no actionable findings remain" is an unbounded loop with no escape hatch. It has no stop condition for the case where repeated findings indicate the *approach* is wrong rather than the patch being incomplete. Session `0f41cdcb` is what that costs.

## Evidence

**Session `0f41cdcb` (sandbox command exemptions), the most expensive session in the 14-day corpus:**

- 17 CLI invocations, 366 tool calls, 87 Edit calls, 1.86 MB session file.
- 19.1M input tokens on the final invocation alone; 58 turns.
- The user pasted **11 consecutive external review findings**, each reporting a *new* sandbox escape in the same mechanism: shell-quoting bypass, shell-expansion bypass, symlink target trust, child-process sandbox-disabling flags, PATH/basename trust, and a documented Claude sandbox-bypass path.
- The agent patched each finding reactively and never questioned the shape of the approach — validating an untrusted command string by parsing it.
- `ahm prime`: not run. `tb__codex_review`: 0 calls. `tb__preflight_checks`: 0 calls.
- **The work was abandoned.** `grep -rn exempt --include=*.rs src/` returns nothing today and no commit landed the feature. All 87 edits were discarded.

**The gap is already proven by the user having to fill it manually.** In session `152976e8` the user typed the missing rule by hand:

> "continue to ask for codex reviews until no issues are reported. We have done it twice. if it exceeds 4 times, stop as this could indicate an issue with the approach."

That is a guardrail the repository should own, not something the user should have to supply per-session.

**Supporting compliance data** (cake sessions with code edits, n=25): `ahm prime` run in 10; `tb__codex_review` available but unused in 2; `tb__preflight_checks` available but unused in 1. Three separate sessions drew explicit user complaints about skipped loop steps — `54e43d0b`: "you didn't start the task, you didn't conduct a review via a subagent, and the preflight check seemed to be prematurely ended"; `94771e8e`: "I had to remind you to run the review despite the instructions in AGENTS.md"; `9088a206`: "if you didn't, run preflight checks".

## Direction tension (record before deciding)

This is workflow guidance, the category the 2026-07-07 direction is skeptical of, and cancelled task 180 was closed with "Not worth adding more workflow guidance." Two things distinguish this case, and the task should not proceed unless they hold up:

1. AGENTS.md governs agents *working on cake*; it is not compiled into cake's own system prompt, so this does not add product-side judgment. The "mechanism over judgment" constraint is about what cake the harness owns.
2. The absence of a stop rule has a measured six-figure-token cost and one fully abandoned change, and the user has already had to supply the rule manually at least once.

If the maintainer judges that the existing routing ("Security-boundary changes require explicit impact analysis and platform-specific verification") should have been sufficient, the correct disposition is to cancel this and instead treat `0f41cdcb` as a model-capability problem. Record whichever way it goes.

## Fix direction

Two small edits, both to AGENTS.md:

1. **Bound step 8.** Add a stop condition: if a third review round still reports findings of the same class, stop patching, treat the approach as suspect, and escalate to a design decision rather than continuing. State what to do on stopping (report the finding class and the suspected design flaw) so the exit is actionable rather than just a halt.

2. **Add a security-boundary escalation rule** to the "Sandbox, Filesystem Access, And Trusted Extensions" route. The route already demands "explicit impact analysis" but supplies no mechanism and no stop condition. Require enumerating the intended bypass classes *before* editing the boundary, and treat a review-reported bypass class that was not enumerated as a signal to revisit the design. `docs/security.md` "Security-sensitive changes" is the natural home for the longer form, with AGENTS.md carrying the pointer.

Keep both additions short. AGENTS.md is loaded on every session in this repository; the operating loop is nine lines and should stay close to that.

**Both edits land.** The direction tension recorded in this task is resolved in favour of implementing; this satisfies the acceptance criterion requiring the tension to be settled in writing.

### Rationale

AGENTS.md governs agents *working on* cake and is not compiled into cake's product system prompt, so this does not put judgment into the harness — the 2026-07-07 "mechanism over judgment" constraint is about what cake the product owns, and is not violated here.

The decisive evidence is that the rule has already been supplied manually by the user. In session `152976e8` the user typed a stop rule by hand ("if it exceeds 4 times, stop as this could indicate an issue with the approach") because the repository did not provide one. A user hand-writing a guardrail per-session is the clearest available signal that the guardrail belongs in the repository. The counterfactual cost is measured: `0f41cdcb` spent 87 edits and 19.1M input tokens across 11 consecutive sandbox-escape findings and was abandoned entirely.

### Agreed scope

Two edits, both small. Keep the operating loop close to its current nine lines.

**1. AGENTS.md operating loop step 8** — replace the unbounded formulation:

> 8. After implementation edits, run a review in a subagent, then perform preflight. If a third round reports findings of the same class, stop patching: report the finding class and the suspected design flaw, and escalate to a design decision.

The threshold is 3, not the 4 the user used in `152976e8`; the escalation is cheap and the failure it prevents is not. Note the exit is actionable — it says what to produce on stopping, not merely to halt.

**2. AGENTS.md sandbox route**, with the long form in `docs/security.md` "Security-sensitive changes":

> Before editing a security boundary, enumerate the bypass classes you intend to defend against. A review-reported bypass class you did not enumerate is a signal to revisit the design, not to add another check.
