# Establish the Runbook Document Category and Its Routing

**Source:** [.ahm/research/topics/skills-vs-runbooks.md](../../research/topics/skills-vs-runbooks.md); maintainer decisions 2026-07-27.

## Problem

`.agents/skills/` currently holds two different kinds of content under one
label. Four of its entries — `auditing-binary-size`, `debugging-cake`,
`debugging-sandbox`, `analyzing-cake-sessions` — are repeatable repository
procedures with numbered steps, prerequisites, expected interpretations, and
recovery actions. They are runbooks, not skills that teach an approach.

There is no runbook location in this repository, so the four conversion tasks
that depend on this one have no destination and no routing story. This task
creates both.

This is also a change to cake's declared content model, not cleanup.
[ADR 002](../../../docs/adr/002-agent-skills.md) explicitly names debugging cake
and evaluating sessions as examples of skill-worthy specialized instructions, so
converting them without amending the ADR leaves the accepted decision
contradicting the tree.

## Decision

Maintainer decisions recorded 2026-07-27:

- Runbooks live in `docs/runbooks/`, a peer of `docs/adr/` and
  `docs/guardrails/`.
- A converted skill is not deleted. Its `SKILL.md` shrinks to frontmatter plus a
  pointer at the runbook, so catalog-based discovery keeps working while the
  runbook owns the content.
- The three upstream-managed skills (`grooming-backlog`, `preflight`,
  `finding-improvements`) are out of scope.

## Scope

1. Create `docs/runbooks/` with an index that states what a runbook is and lists
   the runbooks the dependent tasks will add.
2. Amend [ADR 002](../../../docs/adr/002-agent-skills.md) with the three-way
   distinction, following the existing Amendment Record convention in that file:
   - **Skill** — teaches a decision frame, capability, or way of approaching work.
   - **Runbook** — owns a repeatable repository operation, including branches,
     safety, evidence, and recovery.
   - **Reference** — records stable formats, commands, and diagnostic
     interpretation.
3. Add runbook routing to [AGENTS.md](../../../AGENTS.md). Each existing
   workflow route should name the runbook that serves it, so an agent that lands
   on the sandbox route finds the sandbox runbook without relying on the skill
   catalog.
4. Establish the pointer-stub shape the dependent tasks will apply, so all four
   conversions look the same.

Do not convert any of the four skills here. This task only creates the
destination, the ADR amendment, and the routes.

## Guardrail

This is a behavior-shaping instruction change under
[docs/guardrails/agent-instructions.md](../../../docs/guardrails/agent-instructions.md).

- **Observed failure:** `.agents/skills/` is a single undifferentiated category,
  so procedures that should be repository-owned and routed from `AGENTS.md` are
  reachable only through cake's skill-discovery mechanism. Completed
  [task 247](../completed/247.md) already recorded that non-cake agents miss
  these files and had to be handed a `.claude/skills` symlink to see them at all.
- **Expected observable change:** an agent working a routed surface (sandbox,
  sessions, build) reaches the corresponding procedure through `AGENTS.md`
  routing rather than only through skill discovery.
- **Verification:** the probe belongs to the dependent conversion tasks, which
  are what actually move content. Record here that verification is deferred to
  them and name the probe: a fresh session given a routed task, checked for
  whether it retrieved the runbook.
