# Kill the Bash tool's process group when its future is dropped (Ctrl-C)

## Summary

At commit `c0b7faa`, Bash children run in their own process group, which means terminal SIGINT does not reach them. When the user presses Ctrl-C, the main select drops the agent-turn future; `kill_on_drop(true)` SIGKILLs only the direct child (bash or sandbox-exec), and the group kill in `terminate_process_group` runs only on the timeout and output-cap paths. Descendants (a `cargo build`, a dev server started by the command) survive as orphans and keep running after cake exits. Hooks and toolbox tools already have RAII drop guards for exactly this; the Bash tool does not.

## Evidence

- `src/clients/tools/bash.rs:535-539` — `process_group(0)` detaches the child from the terminal's foreground group.
- `src/clients/tools/bash.rs:610-635` — `terminate_process_group` is called only on `hit_cap` and timeout, not on drop.
- `src/main.rs:1004-1027` — Ctrl-C wins the `tokio::select!`, dropping the in-flight bash future.
- `src/hooks.rs:600-642` (`HookProcessGuard`) and `src/clients/tools/toolbox.rs:92` (`ToolboxProcessGuard`) — the existing in-repo pattern to copy.

## Fix Direction

Add an RAII guard (mirroring `HookProcessGuard`/`ToolboxProcessGuard`) armed after spawn in `execute_bash_with_args`, defused on normal completion, so any drop of the future (Ctrl-C, cancellation, early error return) SIGKILLs the whole process group. Keep the existing timeout/cap kill paths; the guard is the safety net, not a replacement.
