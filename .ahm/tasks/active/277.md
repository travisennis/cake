# Add project-customizable sandbox paths via [sandbox] settings

## Objective

Allow projects to customize the filesystem sandbox through `settings.toml` instead of relying on hard-coded tool-specific paths. Replace the current hard-coded codex paths with user-configured `[sandbox]` entries.

## Motivation

Projects sometimes need to run other AI CLIs or custom binaries from outside the default sandbox paths. Today `~/.local/bin/claude` is blocked, and `~/.codex` paths are hard-coded in the source. We want a mechanism where projects (or global user settings) can declare which extra paths the sandbox should allow.

## Decisions

- Settings schema: structured `[sandbox]` section with two keys:
  - `read_only` — read + execute access
  - `writable` — read + write + execute access
- Merge semantics: **union** across global settings, project settings, and selected profile (same as `directories`).
- Tilde expansion: support `~` in `[sandbox]` keys **and** in the existing `directories` key (fixing latent silent-ignore bug).
- Security: no deny-list and no trust prompt in this task. Document the accepted trust model: project-level `.cake/` config is fully trusted.
- Layering: `[sandbox]` paths feed both the OS sandbox (Seatbelt/Landlock) **and** the in-process `validate_path` checks for Read/Edit/Write/Grep tools.
- Read-only policy: under `--sandbox read-only`, `[sandbox].writable` paths are demoted to read-only, matching current `directories` behavior.
- Startup visibility: file-only log warnings for now; user-visible presentation to be designed later.
- Codex hard-coded paths: remove them as a separate commit after the `[sandbox]` mechanism lands. Migration is a one-time addition to `~/.config/cake/settings.toml`.

## Implementation outline

1. **Settings schema and loading** (`src/config/settings.rs`)
   - Add `[sandbox]` section with `read_only: Vec<String>` and `writable: Vec<String>`.
   - Add to `ProfileSettings` overlay.
   - Merge as union across global, project, and profile.
   - Extract `expand_home()` from `src/config/skills.rs` into a shared config helper and use it for `[sandbox]`, `directories`, and keep `skills.path` using it.

2. **ToolContext plumbing** (`src/clients/tools/mod.rs`, `src/main.rs`)
   - Load `[sandbox].read_only` paths into `additional_dirs`.
   - Load `[sandbox].writable` paths into `settings_dirs`.
   - Ensure canonicalization and missing-path warnings happen once at settings-load time.

3. **SandboxConfig** (`src/clients/tools/sandbox/mod.rs`)
   - No structural changes required if paths are merged into existing `additional_dirs`/`settings_dirs`.
   - Verify read-only policy demotes writable paths correctly.

4. **macOS Seatbelt** (`src/clients/tools/sandbox/macos.rs`)
   - For file paths in the readable set, emit `allow_literal("file-read*", path)`.
   - For directory paths, continue using `allow_subpath`.
   - Ancestor literals are already generated from `config.readable`.

5. **Linux Landlock** (`src/clients/tools/sandbox/linux.rs`)
   - `path_beneath_rules` already handles files and directories; verify behavior with tests.

6. **Tests**
   - Settings merge and tilde expansion tests.
   - macOS: test that a file path is readable/executable and a sibling file is denied.
   - Linux: same, or state platform verification gap per guardrail.
   - Read-only policy demotion test.

7. **Codex removal commit**
   - Remove hard-coded codex entries from `extend_with_toolchain_paths()` (including macOS `Library/` variants).
   - Remove or update corresponding test expectations.
   - Add codex paths to personal `~/.config/cake/settings.toml`.

8. **Documentation**
   - Update `docs/configuration.md` with `[sandbox]` examples, merge behavior,
     and `~` expansion.
   - Update `docs/security.md` with the trust decision and boundary relaxation.

## Acceptance criteria

- A project can declare `[sandbox].read_only = ["~/.local/bin/claude"]` and run `claude` from sandboxed Bash.
- A project can declare `[sandbox].writable = ["~/.claude", "~/.cache/claude"]` so Claude Code can write its state.
- Hard-coded codex paths are removed from source; codex functionality continues to work via user settings.
- `directories = ["~/foo"]` now expands `~` and works.
- All tests pass on macOS and Linux (Linux gap stated if not tested).
- Configuration and security authorities reflect the new behavior without a
  second implementation description.

## Risks / remaining concerns

- Backward compatibility: removing codex hard-coding is a breaking change for users who relied on it without configuring settings. Migration is documented.
- Security: project-level `.cake/settings.toml` grants are trusted by design; no deny-list in this task.
