# Capture provider termination metadata for incomplete model turns

**Source:** Investigation of sessions `63e582e4-f65a-4d02-8bff-3f25f8c7d454`
and `f5a7ddf3-ff1d-4de3-8abf-3453caaaeee9` on 2026-07-29.

## Problem

The final Chat Completions request in session `63e582e4` returned HTTP 200 with
314 output tokens, all classified as reasoning, and no assistant message. Cake
recorded a `cut_off` outcome, but the persisted session, telemetry, and log do
not retain the provider's termination reason. `ChatChoice.finish_reason` was
removed as unused in task 130, and the Responses API DTO similarly omits
response-level incomplete/status details.

Without provider termination metadata, Cake cannot distinguish token exhaustion,
content filtering, a provider-declared incomplete response, or a nominal stop
that happened to contain reasoning only. This prevents evidence-backed
diagnosis and makes a safe automatic-recovery policy harder to classify.

## Scope and Direction

- Introduce a provider-neutral termination classification on the internal
  single-turn result.
- Populate it from Chat Completions `finish_reason`.
- Populate the equivalent status and incomplete details from Responses API
  responses when providers return them.
- Preserve unknown provider values and tolerate missing fields.
- Add the termination classification to API-attempt telemetry and relevant
  cut-off diagnostics without persisting raw provider responses or changing
  model-visible conversation history.
- Keep telemetry additions backward-compatible and optional.
