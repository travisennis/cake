# Deduplicate the full verification gate between handoff guidance and pre-push hook

## Context

`CONTRIBUTING.md` (line ~157) requires running `just ci` "before final handoff and before pushing", while the pre-push hook (`CONTRIBUTING.md` line ~29, `just pre-push`) already runs `just ci` mechanically. The same full gate is therefore demanded at two boundaries, and the handoff copy is enforced only by prose.

`just ci` is heavy (justfile line ~85): `rust-version-check check-linux fmt-check clippy-strict clippy-no-default-features test-all-features check-coverage lint-imports lint-module-size` — two full clippy passes, all-features tests, and an llvm-cov instrumented coverage build with the cargo-crap regression check. That is a multi-minute worker feedback loop paid on every agent handoff, even for small diffs.

## Work

1. Time `just ci` cold and warm; record the numbers in this task.
2. Decide the per-handoff gate policy: keep the full gate, or scale the handoff requirement to the narrowest checks matching the diff (e.g. fmt + clippy + affected tests) while the pre-push hook retains the full gate.
3. Update `CONTRIBUTING.md` (verification section) and any guardrail that repeats the rule.

## Verification

This is a behavior-shaping instruction change: follow the "Agent-Facing Instruction Changes" section of `docs/guardrails/documentation.md` (name the motivating evidence, state the expected behavior change — shorter handoff loops without more red pushes — and run or defer a fresh probe).

## Acceptance criteria

- Measured `just ci` durations recorded.
- One documented gate policy with a single authoritative home; no contradictory statements between CONTRIBUTING.md, guardrails, and hooks.
