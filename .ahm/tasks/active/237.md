# Add context_window to Model Configuration

**Created:** 2026-07-07
**Source:** 2026-07-07 backlog triage (bitter-lesson audit V6 / Phase 1 item 1). Prerequisite for task 208.

## Problem

`ModelConfig`/`ModelDefinition` has no `context_window` field, so the harness cannot know a model's input budget. Context overflow is discovered only after a failed request by string-parsing the provider's error prose: `parse_context_overflow` (`src/clients/retry.rs`, around line 404) splits on "context limit", `'+'`, and `'>'` to extract numbers from a sentence. One integer of configuration replaces the most brittle string surgery in the codebase, and task 208 (context window management, P1) cannot act preemptively without it.

## Fix Direction

- Add an optional `context_window` (tokens) to the model definition in settings (`src/config/model.rs` / `src/config/settings.rs`).
- Thread it to where per-turn `Usage` is already accumulated so the agent loop can compare consumption against the window.
- When configured: expose remaining budget (at minimum log/telemetry; task 208 decides the action policy).
- Keep `parse_context_overflow` only as a fallback for models without the field; do not extend it.
- Settings shape is a documented compatibility surface — add the optional key
  to `docs/configuration.md`.

## Relevant Files

- `src/config/model.rs`, `src/config/settings.rs` — model definition
- `src/clients/retry.rs` — `parse_context_overflow` demoted to fallback
- `src/clients/agent.rs` / usage accumulation — comparison point
- `docs/configuration.md`
