# Convert analyzing-cake-sessions to a Runbook With References

**Source:** [.ahm/research/topics/skills-vs-runbooks.md](../../research/topics/skills-vs-runbooks.md); maintainer decisions 2026-07-27. Depends on task 300 for the destination, the ADR amendment, and the stub shape.

## Problem

`.agents/skills/analyzing-cake-sessions/` is a five-phase analysis procedure
with an output contract and a checklist, plus two supporting reference files
(`reference/jq-recipes.md`, `reference/edit-tool-session-analysis.md`). The
procedure is a runbook; the two reference files are references. The whole
directory is currently labeled a skill.

This is the one conversion of the four that exercises the runbook/reference
split, so it sets the pattern for how a runbook carries supporting material.

## Scope

1. Move the phased procedure to `docs/runbooks/analyzing-cake-sessions/` — a
   directory rather than a single file, because of the references.
2. Keep `jq-recipes.md` and `edit-tool-session-analysis.md` as references beside
   the runbook, loaded on demand rather than inlined. Preserve the progressive
   disclosure the current skill already uses.
3. Preserve the quality-scoring appendix behavior. The current description
   distinguishes "how well did cake do" (append the Phase 5 appendix) from "what
   went wrong" (do not). That conditional is the useful judgment in this
   procedure and must survive the move intact.
4. Reduce `.agents/skills/analyzing-cake-sessions/SKILL.md` to the pointer stub
   shape established by task 300 — frontmatter with the existing `name` and
   multi-line `description` preserved verbatim, plus a pointer at the runbook.
   Do not delete the skill.
5. Add the runbook to the sessions route in [AGENTS.md](../../../AGENTS.md) and
   cross-link from [docs/integrations.md](../../../docs/integrations.md).

Preserve the existing `description` text exactly. It is a long, deliberately
trigger-rich string and it is what drives retrieval.

## Note On Coupling

This runbook is also the evidence mechanism named by
[docs/guardrails/agent-instructions.md](../../../docs/guardrails/agent-instructions.md):
the guardrail tells agents to verify instruction changes using session files and
this procedure. Moving it changes where that guardrail points, so update the
guardrail's reference in the same change. This runbook is what the sibling
conversion tasks' probes will use.

## Guardrail

Behavior-shaping change under
[docs/guardrails/agent-instructions.md](../../../docs/guardrails/agent-instructions.md).

- **Observed failure:** the procedure is reachable only through cake's skill
  catalog. Completed [task 247](../completed/247.md) recorded non-cake agents
  missing `.agents/skills/` entirely.
- **Expected observable change:** an agent asked to analyze a session reaches
  the runbook through the sessions route, still loads the `jq` reference only
  when needed, and still appends the scoring appendix only for
  evaluation-phrased requests.
- **Verification:** fresh-session probe — give a new agent session a real
  session UUID to analyze and check that it retrieved the runbook, produced the
  findings report, and made the correct appendix decision. This procedure is
  itself the tool for reading that probe's session.
- **Ordering:** run this probe before the sibling conversions rely on it.
