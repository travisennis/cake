# Route Fixed Output Budgets Through a [limits] Settings Section

**Created:** 2026-07-07
**Source:** 2026-07-07 backlog triage (bitter-lesson audit V5 / Phase 1 item 2).

## Problem

Several output/tool budgets are compiled constants that encode "context is scarce" assumptions calibrated to 2025 context sizes, and none can be changed without a release:

- `BASH_OUTPUT_MAX_BYTES` = 50,000 (`src/clients/tools/bash.rs:26`)
- `BASH_READ_CAP` = 100,000 (`src/clients/tools/bash.rs:30`)
- Read `DEFAULT_END_LINE` = 200 lines (`src/clients/tools/read.rs:7`)
- Read `MAX_OUTPUT_BYTES` = 100,000 (`src/clients/tools/read.rs:8`)
- `HOOK_OUTPUT_LIMIT` = 64KB (`src/config/hooks.rs:16`)

`MAX_EDITS_PER_CALL` is deliberately excluded: the Edit tool is frozen pending the task 234 telemetry decision.

## Fix Direction

- Add a `[limits]` section to settings.toml with keys for each constant; current values become the defaults so out-of-the-box behavior is unchanged.
- Plumb through `ToolContext`/settings loading to the consuming tools.
- Follow-on (not this task): scale defaults from `context_window` when present.
- Settings shape is a documented compatibility surface — add the keys to
  `docs/configuration.md`.

## Relevant Files

- `src/config/settings.rs` — new section
- `src/clients/tools/bash.rs`, `src/clients/tools/read.rs`, `src/config/hooks.rs` — consume configured values
- `src/clients/tools/mod.rs` — `ToolContext` plumbing if needed
- `docs/configuration.md`
