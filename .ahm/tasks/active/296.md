## Comments

**2026-07-27T11:19:08-04:00** — Hook matchers currently match only on the event source (tool name for PreToolUse/PostToolUse/PostToolUseFailure, session reason for SessionStart). There is no way to filter on tool input content, e.g. firing a PostToolUse hook only when Bash runs `ahm task complete` or `git commit`.

Use case: a PostToolUse hook that reminds the agent to record mistakes/learnings/desires after finishing work — firing only on Bash commands like `git commit`, `ahm task complete`, or `git push` rather than on every tool call or only at session start.

The matcher grammar would need an optional content pattern:

  Bash(ahm task complete|git commit)

The payload is already available at dispatch time (tool_input_json, tool_input) but the current HookMatcher only inspects the source, not the payload. Implementation would touch HookMatcher::matches() and possibly the matcher parse grammar in the JSON config.
