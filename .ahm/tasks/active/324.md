# Measure Edit failure taxonomy after tool-description changes

## Summary

## Blocker

Blocked on #298 — AGENTS.md conformance report must be implemented first.

Re-measure Edit failure taxonomy ~2 weeks after task 297 to see if documenting read-truncation and post-edit staleness reduces the `no_match` share below the 60% baseline.

## Baseline (from task 297)

Edit fails on 11.5% of calls (128 of 1,116). The `no_match` class dominates at 77 failures — **60% of all Edit failures** — with two primary causes:

1. **Read truncation (34 of 35 `no_match`)** — model composed `old_text` from content outside the returned lines after a ranged/partial read.
2. **Post-edit staleness (31 of 77 `no_match`)** — a successful Edit landed, then a later Edit targeted text from a read that predated it.
3. **Field-name confusion (12 of 30 invalid-argument failures)** — wrong field names like `new_string` instead of `new_text`.

## Changes under test

Three tool descriptions were updated on 2026-07-30 (commit `3006981`):

- `read-description.txt` — warns that ranged reads truncate and `old_text` must not span unread regions.
- `edit-description.txt` — notes that edits invalidate prior reads; clarifies `old_text`/`new_text` vs `old_string`/`new_string`.
- `bash-description.txt` — names `rg` for content search; tells models not to prefix with `cd`.

## Re-testing steps

Requires task 298 (session-metrics conformance report) to be implemented first — it provides the script that makes the taxonomy re-runnable as a single command.

1. Collect a fresh session sample of comparable size (~140 sessions, ~1,100 Edit calls) spanning ~2 weeks after `3006981` landed.
2. Run the conformance report script from task 298 to classify Edit failures into the same taxonomy buckets (`no_match`, `invalid_argument`, `tool_error`, `permission_denied`, `other`).
3. Break down `no_match` failures by cause (read-truncation, post-edit staleness, other).
4. Compare against baseline:
   - Is the `no_match` share below 60%?
   - Are read-truncation failures reduced?
   - Are post-edit-staleness failures reduced?
   - Are `new_string`/`new_text` confusion errors eliminated?
5. Report results and decide whether additional tool-description changes or a different intervention is needed.
