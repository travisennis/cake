# Low-severity fixes from the 2026-07 code review

## Summary

Bundle of small, independent fixes surfaced by the July 2026 full-code review at commit `c0b7faa`. Each is mechanical; none changes compatibility surfaces.

## Items

1. **String-continuation typo** — `src/clients/tools/bash.rs:352-356`: the `\` line continuation strips the following indentation, rendering "could not create**secure** directory" (missing space) in the binary-output error message.
2. **Stale comment** — `src/clients/tools/read.rs:118`: comment says "absolute default of 500"; `DEFAULT_END_LINE` is 200 (`read.rs:7`).
3. **Unclamped Bash timeout argument** — `src/clients/tools/bash.rs:54`: the model-supplied `timeout` is used raw; `0` fails instantly and huge values are accepted. Clamp to a sane floor/ceiling (e.g. 1..=600s or a documented max).
4. **Write validation symlink asymmetry** — `src/clients/tools/write.rs:143-152`: the new-file path compares the canonicalized base against *non-canonicalized* cwd/temp/settings dirs, while the existing-file path (`mod.rs:765-775`) canonicalizes each dir before comparing. Creating a new file under a symlinked settings dir can be rejected while editing an existing file there succeeds. Align the new-file checks with `path_starts_with`.
5. **Seatbelt path escaping** — `src/clients/tools/sandbox/macos.rs:511-515`: `escape_path` handles only `\` and `"`; a newline in a configured path would break out of the profile string literal. Reject or escape control characters in emitted profile paths.
