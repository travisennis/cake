# Move Per-Model Provider Quirks Into Model Configuration

**Created:** 2026-07-07
**Source:** 2026-07-07 backlog triage (bitter-lesson audit V7/V8 / Phase 1 item 4).

## Problem

Two provider quirks are compiled into code:

- `requires_reasoning_content_tool_call_fallback` is `model.contains("kimi")` (`src/clients/provider_strategy.rs:116`). The next quirky model requires a release.
- `demote_developer_to_user` runs unconditionally for all Chat Completions providers (`src/clients/provider_strategy.rs:127`) because *some* providers reject the developer role — knowledge about a few endpoints applied universally, discarding role fidelity everywhere.

## Fix Direction

- Add optional per-model (or per-provider) settings keys, e.g. `supports_developer_role` and `reasoning_content_tool_call_fallback`.
- Replace the `contains("kimi")` sniff with configuration; ship a default that preserves behavior for kimi models (embedded default or documented example).
- Make developer-role demotion conditional on config. Compatibility note: provider/backend behavior is a documented surface — the shipped default should preserve today's universal demotion, with config opting a provider/model *out*; flipping the default is a separate decision.
- Update `docs/configuration.md`; keep provider mechanics in code and request
  snapshots.

## Relevant Files

- `src/clients/provider_strategy.rs` — both quirks
- `src/config/model.rs`, `src/config/settings.rs` — new optional keys
- `docs/configuration.md`
- Chat Completions request snapshot tests
