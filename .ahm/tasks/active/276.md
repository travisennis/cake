# Evaluate sandbox-exemption list vs. nested-sandbox fallback

# Evaluate Sandbox-Exemption List (Approach 4) and Decide vs. Approach 2

## Problem

After implementing a graceful nested-sandbox fallback (Approach 2, task 275), we need to evaluate whether a more explicit configuration-driven solution — a sandbox-exemption list — is worth adding on top or as a replacement. The exemption list would let users declare specific command names (e.g. `codex`, `claude`) that should always bypass cake's sandbox, regardless of whether a nested sandbox is detected.

This task evaluates Approach 4, compares it against the already-implemented Approach 2, and recommends whether to implement it, skip it, or implement it as a complementary feature.

## Evaluation Criteria

- **Security model impact**: Does the exemption list introduce new risk? Is it additive to or duplicative of Approach 2?
- **User experience**: Is the configuration surface (CLI flag + settings.toml key) worth the complexity? When would a user need it?
- **Implementation cost**: Approximate lines changed, files touched, tests needed.
- **Maintenance burden**: Command-name parsing fragility, ongoing test overhead, documentation.
- **Use case coverage**: Are there scenarios where Approach 2 is insufficient and Approach 4 would help? (e.g., exempting a command that isn't already outer-sandboxed but needs paths outside cake's sandbox profile)

## Relevant Files

- `src/clients/tools/mod.rs` — `ToolContext` struct and constructors.
- `src/clients/tools/bash.rs` — sandbox gate logic in `execute_bash_with_args()`.
- `src/clients/tools/sandbox/mod.rs` — `detect_macos_platform()` and nested-sandbox fallback from task 275.
- `src/main.rs` — `ToolContext` construction site.
- `src/config/settings.rs` — settings TOML schema.
- `src/cli/mod.rs` or `src/cli/debug.rs` — CLI command structure.

## Task Output

A written recommendation in the task body:

1. Analysis of Approach 4's incremental value over Approach 2.
2. Identification of any gaps Approach 4 fills that Approach 2 does not.
3. Assessment of whether the implementation cost is justified.
4. A clear decision: **Implement Approach 4**, **Skip Approach 4** (Approach 2 is sufficient), or **Do Both** (Approach 4 as optional overlay on Approach 2).

If "Do Both" or "Implement", include a fix direction sketch.
