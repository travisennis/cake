# Standardize and enforce Conventional Commit scopes

## Summary

Define a small, stable Conventional Commit scope vocabulary based on Cake's
durable architecture boundaries, enforce it through Cocogitto, and document how
contributors choose a scope. This prevents one-off implementation scopes from
fragmenting git history and generated changelog labels.

## Context

Cake currently validates Conventional Commit syntax but does not constrain the
optional scope. Recent history includes overlapping or overly specific scopes
such as `tasks`/`ahm`, `edit`/`tools`, `bash`/`bash-safety`, `exit-code`, and
comma-separated multi-scopes. Fine-grained `.ahm` `area:*` labels serve backlog
routing and should not define the coarser commit scope taxonomy.

Use the architecture domains as the initial allowlist:

- `agent`
- `cli`
- `config`
- `extensions`
- `prompts`
- `providers`
- `sandbox`
- `session`
- `tools`

`extensions` covers the trusted hook and toolbox extension surfaces. The
specific function, file, tool, or mechanism belongs in the commit subject; for
example, prefer `refactor(cli): simplify input error classification` over
`refactor(exit-code): ...`.

## Implementation Direction

- Add the approved list to the top-level `scopes` setting in `cog.toml`, making
  Cocogitto the machine-readable authority.
- Expand the Git and commits section of `CONTRIBUTING.md` with the selection
  rules and a short scope-to-subsystem explanation. Reference that authority
  from `AGENTS.md` without duplicating the vocabulary.
- Keep scopes optional and require at most one approved scope. Cross-cutting
  changes choose the subsystem that owns the resulting behavior; repository-wide
  work remains unscoped.
- Do not rewrite existing history. Assess and document the effect of the new
  allowlist on any history-wide `cog check` workflow before enabling one.

## Acceptance Notes

- [ ] `cog.toml` contains the agreed stable scope allowlist
- [ ] The commit-message hook accepts approved and unscoped commits and rejects
      an ad hoc scope
- [ ] `CONTRIBUTING.md` explains when to use, omit, or add a scope and distinguishes
      commit scopes from `.ahm` area labels
- [ ] Existing changelog generation still handles historical commits without a
      history rewrite
- [ ] Focused Cocogitto verification and documentation checks pass
