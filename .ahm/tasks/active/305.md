# Convert preflight to a Runbook and Route It From the Operating Loop

**Source:** [.ahm/research/topics/skills-vs-runbooks.md](../../research/topics/skills-vs-runbooks.md); 2026-07-27 review of the local preflight copy against the shared collection. Amends the out-of-scope decision recorded in [task 300](../completed/300.md).

## Problem

Two separate defects share one file.

**1. `AGENTS.md` step 8 is the worst-routed step in the operating loop.**
`AGENTS.md:18` says "then perform preflight" — a bare noun with no link. Every
other step in that loop names its authority (`ahm prime`, `ARCHITECTURE.md`,
`ahm context plan`). Preflight is the only unconditional, every-change step in
the loop, and it is the only one that resolves solely through cake's
skill-catalog matcher.

That is backwards. Description-matched catalog retrieval earns its keep for
*situational* content: hit a Seatbelt denial, the description matches, pull
`debugging-sandbox`. A step that must run on every change does not need
retrieval — it needs a link. The skills-vs-runbooks research already records
that agents have been measured skipping preflight and other operating-loop
steps.

**2. The "upstream-managed, out of scope" premise in task 300 is stale.**
`.agents/skills/preflight/SKILL.md` has already forked from
`Projects/skills/skills/preflight/SKILL.md`. Observed 2026-07-27:

| Upstream | Cake's copy |
| --- | --- |
| `.agents/.tasks/index.md` | `.ahm/tasks/active/` |
| `.agents/exec-plans/active/` | `.ahm/exec-plans/active/` |
| `docs/design-docs/`, "Design docs:" | "durable contract/security/architecture docs", "Durable docs:" |
| (absent) | `ahm context task`, `ahm context plan`, `ahm task show <id>` |

Cake is already maintaining a cake-specific fork; it is simply not labeled as
one, and nothing prevents the next upstream edit from silently reintroducing
`docs/design-docs` into this repository's mandatory review step. Conversion does
not create divergence. It names divergence that already exists.

## Decision

- Move the whole file. Do **not** take the split the research note floats
  (three review lenses stay a skill, numbered procedure becomes a runbook). The
  scale table at `.agents/skills/preflight/SKILL.md:25` is what makes the lenses
  actionable, and mid-review is exactly when an agent is least likely to follow
  a cross-file link.
- Destination is `docs/runbooks/preflight.md`, not `CONTRIBUTING.md` (that file
  is the command catalog and verification policy; preflight is a review
  procedure, not a check to run) and not `docs/guardrails/` (guardrails there
  govern what evidence an *edit* requires, not how to conduct a review).
- Keep the pointer stub. `.claude/skills -> ../.agents/skills` (completed
  [task 247](../completed/247.md)) is what makes `/preflight` work in Claude
  Code; deleting the directory entry costs the maintainer the slash command, and
  the frontmatter `description` is the only retrieval affordance a bare doc file
  does not have.
- After the move, cake's runbook owns cake and the shared collection owns the
  generic version. Neither tracks the other. Record that so a future sync
  attempt does not reintroduce the upstream vocabulary.

## Scope

1. Link the preflight document from `AGENTS.md:18`. **This is separable and can
   land ahead of task 300** — it is a one-line edit against the current
   `.agents/skills/preflight/SKILL.md` path and probably captures most of the
   measurable value here. Do not let the content-model work gate it.
2. Move the procedure to `docs/runbooks/preflight.md`, retargeting the
   `AGENTS.md:18` link.
3. Reduce `.agents/skills/preflight/SKILL.md` to the pointer-stub shape
   established by task 300, `name` and `description` byte-identical.
4. Amend [task 300](../completed/300.md)'s out-of-scope list: preflight is no longer
   upstream-managed. Cite the fork evidence above. `grooming-backlog` and
   `finding-improvements` also differ from their upstream copies and are worth
   re-checking on the same grounds, but they stay out of scope here.
5. While moving, reconcile the runbook's context list against this repository's
   actual authorities: `ARCHITECTURE.md`, `docs/integrations.md`,
   `docs/security.md`, `docs/configuration.md`, `docs/adr/`,
   `docs/guardrails/`, and `just ci` as the documented final validation command.
   The forked copy generalizes several of these into prose that no longer names
   a file an agent can open.

## Guardrail

Behavior-shaping change under
[docs/guardrails/agent-instructions.md](../../../docs/guardrails/agent-instructions.md).

- **Observed failure:** agents have been measured skipping preflight and other
  operating-loop steps; see
  [.ahm/research/topics/skills-vs-runbooks.md](../../research/topics/skills-vs-runbooks.md).
  Unlike the other four conversions, this one has direct evidence of the failure
  it is meant to fix rather than only the discoverability argument from
  [task 247](../completed/247.md).
- **Expected observable change:** a fresh session that finishes an ordinary code
  change reaches preflight, and reaches it by following the `AGENTS.md` link
  rather than by matching the skill catalog.
- **Verification:** fresh-session probe — give a new session an ordinary
  small code change and check (a) whether it performed preflight at all, and
  (b) which path it took to the document. Run this against the step-1 link
  alone before the move, so the routing effect is attributable separately from
  the relocation.
- If the probe is not run, record that verification is deferred and name it.

## Follow-ups

Preflight being mandatory makes it a candidate for mechanism rather than
instruction, which would outrank the document-placement question entirely.
`.cake/hooks/remind-self-reflection.sh` already fires on `SessionStart`; a hook
on the pre-commit path could enforce the step in a way no document placement
can. That is closer to the mechanism-over-judgment direction than either
document choice here. File separately if the probe in this task shows routing
alone does not fix the skipping.
