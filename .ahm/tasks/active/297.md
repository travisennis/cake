# Document the read-truncation cliff and post-edit staleness in tool descriptions

**Source:** Multi-session analysis 2026-07-27 (143 sessions, 2026-07-13 .. 2026-07-27, 7,504 tool calls, 1,116 Edit calls, 2,400 Read calls).

## Problem

Edit fails on 11.5% of calls (128 of 1,116). The dominant class is now `old_text` not found — 77 failures, 60% of all Edit failures — and the session evidence points at two specific causes that the current model-facing tool text does not mention.

**1. Reads silently truncate, and models edit against material they never saw.**

`63.4% of all Read calls return truncated content` (1,522 of 2,400). Of the `no_match` failures where a Read of the same file occurred within two tool calls, **34 of 35 followed a partial/ranged read**. The model saw a window, then composed `old_text` spanning content outside it.

`read-description.txt` currently says only:

> - Returns a "N more lines" note when the file extends beyond the requested range.

It states the mechanism but never warns what the mechanism costs, and never connects it to Edit.

**2. A successful edit invalidates the model's view, and it edits from the stale view anyway.**

**31 of the 77** `no_match` failures are stale-after-own-edit: a successful Edit landed, then a later Edit targeted text from a read that predated it. `e1b96a59` hit this five times on `src/hooks.rs` in one session (Edit calls at session lines 236, 355, 358, 369, 372). `f84675c1` hit it three times across `src/config/worktree.rs` and `tests/stdin_handling.rs`.

`edit-description.txt` does not mention that prior edits invalidate earlier reads.

**3. Field-name confusion is a measurable, trivially fixable residue.**

12 of the 30 invalid-argument failures are wrong field names, not malformed JSON — 7 sent `new_string` instead of `new_text` (the Claude Code spelling), plus `new_head`, `new_name`, and 2 rejected `path` placements. JSON repair (shipped in `384401c`) cannot fix a wrong field name.

**4. Search tooling is unnamed, so models default to the slow option.**

Bash carries 810 `grep` invocations against 40 `rg`, plus 201 `find`. `bash-description.txt` says only "Content search: Use commands via Bash" — it names no tool. Separately, 2,766 of 3,782 Bash commands (73%) redundantly prefix `cd <abs path> &&` even though the description already states the working directory persists, and 2 calls invoked a nonexistent `Grep` tool (`Error: Unknown tool: Grep`).

## Direction fit

These are edits to `*-description.txt`, which AGENTS.md names as "the authority for schemas and model-visible text" for the tools surface. This is tool documentation, not an in-loop coaching heuristic — it adds no runtime tracking, no thresholds, and no compiled judgment, and so does not repeat the pattern rejected in cancelled task 198. Every claim above is measured, satisfying the "no unmeasured model compensation" constraint.

## Fix direction

Keep the additions short; these files are paid for on every request.

- `read-description.txt` — state that output is truncated when the file exceeds the requested range, and that `old_text` for a subsequent Edit must never be composed from a region that was not actually returned.
- `edit-description.txt` — state that each successful edit invalidates any view of that file taken before it, and that a second edit to the same file should re-read the target range first. Name the parameters explicitly as `old_text`/`new_text` and note they are not `old_string`/`new_string`.
- `bash-description.txt` — name `rg` as the content-search tool instead of the unqualified "use commands via Bash"; strengthen the working-directory sentence so the redundant `cd` prefixing has a reason to stop.

Do not add runtime detection, counters, or nudges — that direction was rejected in task 198.
