# Establish Cyclomatic Complexity Targets and Standardize Coverage-First Refactoring Approach

## Summary

Establish project-wide targets for cyclomatic complexity (CC) and CRAP
scores, and standardise the coverage-first refactoring workflow as the
method for reducing complexity across all modules.

## Background

`cargo-crap` analysis (2026-07-30) revealed 17 functions with CC ≥ 15 and
CRAP > 200, concentrated in bash safety, parser, exit-code classification,
worktree glob matching, and configuration assembly. All are untested
(coverage column reports 0% on every entry). The CRAP metric penalises
untested high-complexity code quadratically — CC 38 with 0% coverage
yields CRAP 1482.

## Targets

### Cyclomatic Complexity (CC)

| Target | Applies To | Rationale |
|--------|-----------|----------|
| CC ≤ 10 | Most refactored functions | Default clippy threshold; achievable via extraction |
| CC ≤ 15 | Inherently dispatch-heavy functions | `is_input_error`, `build_client_and_session`, `load_with_profile` — where a match on many variants or structural config branching is intrinsic |
| CC ≤ 20 | Grandfathered structurally complex loop | `Agent::send` — the agent-turn loop has inherent branching; acceptable only with ≥ 80% coverage |

### CRAP (Change Risk Anti-Patterns)

| Target | Condition |
|--------|-----------|
| CRAP ≤ 30 | Every function after the refactoring pass |
| CRAP ≤ 15 | Stretch goal for CC ≤ 10 functions with ≥ 90% coverage |

CRAP formula: `comp² × (1 − coverage)³ + comp`. A CC-10 function needs
~70% coverage to hit CRAP ≤ 20, or 100% coverage to hit CRAP ≤ 10. A
CC-15 function needs ~85% coverage to hit CRAP ≤ 25.

### Coverage Thresholds (per-function, line + branch)

| Band | Requirement |
|------|------------|
| ≥ 80% | Required before refactoring a function |
| ≥ 90% | Required for functions remaining at CC > 10 |

## Approach

**Coverage first, then refactor.** This is the only path that makes the
CRAP metric work for us rather than against us.

1. Write focused tests for each high-CC function, achieving ≥ 80% line and
   branch coverage. This alone collapses CRAP by orders of magnitude
   (e.g., CC 38 → CRAP ~42 at 80% coverage).
2. Run `cargo-crap` with the LCOV file to confirm CRAP drop.
3. Refactor: extract sub-functions, replace match ladders with lookup
   tables or typed dispatch, simplify boolean logic, and reduce nesting.
4. Re-run `cargo-crap` to confirm CC target is met without regressing
   coverage.
5. Update `.clippy.toml` cognitive-complexity thresholds if needed, and
   add per-function allows only with documented justification.
