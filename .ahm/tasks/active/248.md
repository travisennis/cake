# Add cake init for Project Scaffolding and Recommended Policy

## Blocker

Blocked on task 241 (Convert bash_safety Into a Declarative Command-Policy
Engine, now Blocked pending ADR acceptance). Task 241 must define the
command-policy substrate before `cake init` can install recommended policy
files. The dependency chain is: 248 → 241 → ADR acceptance.

## Problem

The Bitter Lesson audit and follow-up discussion identified a useful setup path: `cake init` should scaffold reviewable project configuration for common cake footguns and recommended feedback. The important distinction is that universal command protections should not be moved wholesale into executable hooks. Core tool feedback stays in core, default command protections should become user-owned command-policy data, and hooks should remain the local/project/org extension point for subjective policy, audit logging, experiments, and repository-specific feedback.

Without a task, this design decision can get lost between task 142 (short-term Bash footgun cleanup), task 153 (no-match output feedback), and task 241 (declarative command-policy engine).

## Relevant Files

- `src/cli/mod.rs` and `src/main.rs` - top-level subcommand plumbing.

- Task 153 - core Bash output feedback for no-match searches.
- Task 241 - declarative command-policy engine prerequisite.

## Direction

Design and implement an explicit `cake init` setup command after task 241 defines the command-policy substrate. Recommended behavior should be opt-in and reviewable:

- `cake init` creates `.cake/` and minimal project scaffolding when absent.
- A recommended policy option installs command-policy data, not universal safety checks as hook scripts.
- A recommended hooks option installs example or starter hooks only for project-specific policy, audit logging, extra context, or subjective feedback.
- Personal-only hooks should go to `.cake/hooks.local.json` or another unshared path; shared project hooks should require a deliberate choice because hooks execute trusted local commands outside the model tool sandbox.
- Generated files should avoid overwriting existing `.cake` files without an explicit force/merge story.

Possible command shape to evaluate:

```text
cake init
cake init --policy recommended
cake init --hooks recommended
cake init --local
```

Do not make this task responsible for inventing the command-policy file format; that belongs to task 241 and its ADR/ExecPlan.
