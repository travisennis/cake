# Establish a regular dependency maintenance workflow

## Summary

Choose and implement a controlled dependency-maintenance workflow for Cake.
The workflow should cover Rust crates, GitHub Actions, Rust toolchain pins,
standalone Cargo-installed developer and CI tools, and versions embedded in
workflow inputs without creating an unmanageable stream of pull requests.

The synthesized research and current recommendation are recorded in
[Dependency Maintenance Workflow](../../research/topics/dependency-maintenance-workflow.md).

## Decision Needed

Choose between Renovate and Dependabot. Renovate currently appears to fit
Cake's mixed dependency surfaces better because custom managers can update
non-manifest pins, while Dependabot offers a simpler GitHub-native operating
model. Keep this task Open until the maintainer selects the automation platform
and decides whether a hosted GitHub App is acceptable.

## Scope

- Inventory and normalize automated dependency surfaces.
- Configure the selected updater's schedule, cooldown, grouping, and pull
  request limits.
- Keep security updates prompt and major versions or MSRV changes manually
  reviewed.
- Decide how the existing scheduled dependency checks should coexist with the
  updater.
- Document the contributor and maintainer workflow.

Automerge is out of scope for the initial rollout unless separately approved
after the review-only workflow has demonstrated reliable behavior.

## Acceptance Notes

- [ ] Record the selected automation platform and rationale.
- [ ] Cover Cargo dependencies and GitHub Actions with native managers.
- [ ] Cover or explicitly disposition Rust, Cargo-tool, `.mise.toml`, and
      workflow-input version pins that native managers do not detect.
- [ ] Configure a weekly cadence, release cooldown, sensible grouping, and a
      bounded number of concurrent pull requests.
- [ ] Keep security updates outside the routine cooldown and keep major-version
      and MSRV changes individually reviewed.
- [ ] Reconcile the updater with `.github/workflows/scheduled.yml`.
- [ ] Add focused validation for the updater configuration and document how
      maintainers triage, defer, and promote dependency updates into ahm tasks.
