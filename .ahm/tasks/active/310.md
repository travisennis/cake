# Bound .worktreeinclude traversal against symlink cycles

## Summary

At commit `e569256`, `.worktreeinclude` collection follows directory symlinks with no cycle detection and no depth cap. A symlink cycle inside the source repository drives unbounded recursion until stack overflow, and a directory symlink pointing outside the repository is traversed and its contents copied into the generated worktree.

Task 270 bounded traversal by *pattern pruning* and fixed glob backtracking; it did not address link-following. This is the remaining unbounded case.

## Problem

`collect_matching_files` recurses on `path.is_dir()`, which follows symlinks. There is no visited-inode (device + inode) set and no recursion depth limit, so `ln -s . self` in a repository that also configures any `**` pattern recurses forever: `any_pattern_could_match_under` returns true for `**` patterns at every depth, so pruning never stops the descent.

Separately, `strip_prefix(base)` succeeds on the uncanonicalized path of a symlinked directory, so a link such as `docs -> /etc` produces relative paths that appear to be inside the repository. Files outside the repository are then copied into the worktree under those names.

## Evidence

- `src/config/worktree.rs:302-358` — `collect_matching_files` recurses on `path.is_dir()` (link-following) with no visited set and no depth cap.
- `src/config/worktree.rs:322-332` — pruning uses `strip_prefix(base)` on the uncanonicalized path, so a symlink target outside `base` still yields an in-repo relative path.
- `src/config/worktree.rs:476-497` — `any_pattern_could_match_under` returns true for `**` patterns regardless of depth, so pattern pruning cannot terminate a cycle.
- `src/config/worktree.rs:344-354` — matched files are copied by relative path with no check that the source resolves under `base`.

## Fix Direction

Decide and implement one containment strategy, then test it. Candidates, roughly in order of preference:

1. Do not follow directory symlinks during collection at all. Use `entry.file_type()` (non-following) and skip symlinked directories, which is the simplest rule to reason about and to document.
2. Follow them, but track visited `(device, inode)` pairs and refuse to re-enter, plus verify that each candidate resolves under the canonicalized `base` before descending or copying.

Whichever is chosen, the documented `.worktreeinclude` behavior must stay accurate: `docs/configuration.md` (and any other place the feature is described) should state what happens to symlinks. Preserve copying of gitignored files at arbitrary real depths, the existing glob syntax, and the explicit-include-under-heavy-directory precedence that task 270 established.

Do not add a dependency for this unless an in-tree fix proves unreasonable.

## Acceptance Notes

- [ ] A repository containing a self-referential directory symlink plus a `**` pattern completes without stack overflow or unbounded work, and the test would fail against the current implementation.
- [ ] A directory symlink whose target is outside the repository does not cause out-of-repo files to be copied into the generated worktree.
- [ ] Symlinked *files* that match a pattern have a defined, tested outcome (copied as content vs. skipped) — pick one and document it.
- [ ] Existing worktree include tests, including pruning and explicit-include precedence, still pass.
- [ ] Documented `.worktreeinclude` semantics describe the symlink rule.
- [ ] `cargo test worktree` and `just ci` pass.
