# Feed hook stdin without blocking so a non-reading hook cannot hang cake

## Summary

At commit `c0b7faa`, `run_command_hook` writes the full JSON payload to the hook's stdin inline, before the hook timeout is applied. The timeout only wraps `child.wait_with_output()`. A hook that never reads stdin blocks the write once the OS pipe buffer (~64 KiB) fills; if the hook also does not exit (or fills its own unread stdout pipe), cake hangs indefinitely and the configured hook timeout never fires. PostToolUse payloads embed the full tool output, so payloads over 64 KiB are routine.

## Evidence

- `src/hooks.rs:706-721` — `stdin.write_all(&input).await` runs before any timeout; only `BrokenPipe` is tolerated.
- `src/hooks.rs:723` — `timeout(command.timeout, child.wait_with_output())` covers only the wait, not the stdin write.
- `src/hooks.rs:331-343` — the PostToolUse payload includes `text_result_for_llm` (full tool output, 50-100 KiB+).
- `src/clients/tools/toolbox.rs:113-120` — the toolbox executor already solves this with a detached writer task: "Feed arguments from a detached task so a tool that never reads stdin cannot block the call."

## Fix Direction

Apply the toolbox pattern to hooks: write stdin from a detached task (or include the write inside the same timeout envelope as the wait). Preserve existing semantics: BrokenPipe stays non-fatal, exit status stays authoritative, and stdin write errors surface the same way they do today when they matter.
