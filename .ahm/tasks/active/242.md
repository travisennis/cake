# Slim system.md to Facts; Move Workflow Coaching to a Profile Fragment

**Created:** 2026-07-07
**Source:** 2026-07-07 backlog triage (bitter-lesson audit V4 / Phase 2 item 9).

## Problem

`src/prompts/system.md` teaches "how to work": narration rules ("Do not narrate your plan before acting"), exploration rules, parallel-call choreography, re-read-before-edit rules, a five-part handoff format, and git-commit quoting guidance that duplicates a bash_safety hard block. These are tuned to the failure modes of 2025-era models — useful defaults today, a compiled ceiling on better models tomorrow, and an always-on prompt tax either way.

## Fix Direction

Depends on task 151 (settings/profile-based system prompt configuration) providing the layering mechanism.

- Reduce the built-in `system.md` to facts and hard policy: identity, environment, the generated tool list (see the registry-generated-tool-list task), and hard policy statements.
- Move the workflow coaching sections into an optional shipped profile prompt fragment that users layer via the profile mechanism — a tunable default, not a compiled belief.
- Delete the git-commit quoting lecture outright (the bash_safety check delivers that guidance at the point of error; per task 142's re-scope).
- Coordinate with the per-path-serialization task, which deletes the same-file Edit/Write echo from `system.md`.
- Prompt shape is a compatibility surface; snapshots will change deliberately. If feasible, compare session metrics (turns, tool calls, failure taxonomies) before/after on the default profile to see whether coaching removal regresses the cheap-model fleet — that data decides how much coaching the shipped default profile keeps.
