# Count Model-Compensation Events in Session Telemetry

**Created:** 2026-07-07
**Source:** 2026-07-07 backlog triage (bitter-lesson audit Phase 4). Extends the telemetry sidecar from task 119.

## Problem

Every compensation cake carries for model weaknesses is currently invisible: there is no way to know whether the current model still needs it. The Bitter Lesson's operational corollary: hand-coded knowledge needs an expiration review, and only measurement can grant it. When a counter flatlines at zero for a model, the compensation is a deletion candidate.

## Fix Direction

Add counters to the per-session telemetry sidecar (`src/session_telemetry.rs`) and surface them in the `scripts/session-metrics` suite:

- `json_repair` applications (arguments actually modified, not fast-path exits)
- bash_safety decisions, per rule id (blocks and warnings) — aligns with the future policy engine
- duplicate-mutation guard rejections today; per-path serialization reorderings once that task lands
- tool-output truncations/spills (bash output cap, read cap)
- context-overflow retries
- Edit invalid-argument failures (already analyzed ad hoc for task 234 — make it a standing counter, since the 234 decision explicitly waits on this data)

Document the review discipline: each counter maps to a compensation; a flatlined counter for a given model triggers a deletion review.

## Relevant Files

- `src/session_telemetry.rs` — sidecar fields
- Call sites: `src/clients/tools/json_repair` path, `bash_safety`, `duplicate_guard`/scheduler, `bash.rs`/`read.rs` truncation, `retry.rs` overflow retry, `edit.rs` parse failures
- `scripts/session-metrics*` — report the counters
- `docs/integrations.md` for telemetry compatibility semantics; code and metrics
  tests for field-level mechanics
