# Prototype Bounded Search and Files Tools

## Summary

At commit `fe8dd67`, prototype additive, disabled-by-default `Search` and `Files` tools that replace common Bash discovery round-trips with compact, bounded, model-friendly results. Use task 306's controlled evaluation harness to determine whether either tool materially improves cheap/local-model correctness or efficiency before proposing any default behavior.

## Blocker

Blocked on task 306. The prototype needs a repeatable baseline and A/B evaluation path before its interface or inclusion can be judged. Keep the production default tool registry unchanged in this task.

## Evidence

- `src/clients/tools/mod.rs:990-1030` tells the model there is no dedicated Glob, Grep, or LS tool and routes directory and content discovery through Bash.
- `src/clients/tools/mod.rs:1034-1040` registers only Bash, Edit, Read, and Write.
- `.ahm/tasks/active/297.md:41-47` records 810 `grep` invocations versus 40 `rg` invocations, 201 `find` invocations, 73% redundant `cd`, and two attempted calls to an unavailable `Grep` tool in the analyzed corpus. That is strong evidence that discovery through free-form shell commands is a recurring tax for weaker models.
- `.ahm/research/sources/fff-search-integration.md:12-14` identifies file and content discovery as the useful portion of the explored design, while lines 34-46 warn that the complete indexed implementation brings heavyweight dependencies and lifecycle complexity. Lines 90-111 sketch bounded schemas and output, and lines 123-130 identify security, binary-size, and lifecycle risks.
- `ARCHITECTURE.md` assigns tool schemas, execution, path validation, and sandbox semantics to the existing tool boundary. The prototypes must reuse that authority rather than create a parallel filesystem policy.

## Fix Direction

Implement two narrowly scoped experimental tools:

- `Files`: find files or directories by a simple path/name pattern under an allowed root, with an explicit result limit and continuation cursor.
- `Search`: search readable file contents using literal or explicitly selected regular-expression matching, with explicit case behavior, optional bounded context, a result limit, and continuation cursor.

Return compact, stable, line-oriented results suitable for small context windows. Define ordering and cursor semantics so pagination is deterministic for an unchanged tree. Reuse the existing `ToolContext` and path-validation rules; never broaden readable roots, follow symlinks outside allowed roots, or acquire trusted-extension authority. Define and test whether ignored files are excluded, including the exact `.gitignore` behavior.

Start with the least-complex implementation that can be evaluated. Compare a small native walker/searcher with a safely invoked `rg`-backed implementation if useful, but do not interpolate model input into a shell command. Validate all executable arguments independently and handle missing executables explicitly. Do not add embeddings, a daemon, a persistent index, file watchers, frecency ranking, MCP infrastructure, or a REPL.

Expose the prototypes to task 306 through an internal or test/evaluation registry option. Do not add a public CLI flag or change the default production tool list in this task.

Likely scope includes focused modules under `src/clients/tools/`, tool schemas and descriptions, registry construction for the experimental path, snapshots, and evaluation fixtures. If the design requires a heavyweight dependency, persistent cache/database, background worker, new external-runtime requirement, or broader filesystem authority, stop and record the decision separately before implementation. Any new dependency requires the repository's dependency and binary-size checks.

## Acceptance Notes

- With the experiment disabled, the default tool registry and provider request snapshots are unchanged.
- Both schemas reject unknown properties, bound every result-producing option, and make literal versus regex behavior unambiguous.
- Results have deterministic ordering, stable continuation behavior for an unchanged tree, compact truncation metadata, and no unbounded file contents.
- Tests cover literal and regex searches, case handling, Unicode paths/content, no matches, invalid patterns, inaccessible paths, ignored files, output limits, pagination without duplicate/omitted results, concurrent calls, and trees containing symlinks or traversal attempts.
- Filesystem and sandbox tests prove the tools cannot read outside configured roots or gain authority from the backend implementation.
- If an `rg` backend is retained, tests prove model-provided values are passed as validated arguments without shell parsing and that absence/failure produces a useful model-visible error.
- Task 306 runs the same search-heavy cases with the baseline tools and each prototype across the chosen cheap/local models. Report task correctness, turns, Bash calls, input/output tokens, wall time, and tool failures separately.
- Record an evidence-based recommendation for neither, one, or both tools. Enabling a tool by default remains a separate compatibility decision and task.
- Run `just check-deps` and the binary-size audit if dependencies change, then run `just ci`.
