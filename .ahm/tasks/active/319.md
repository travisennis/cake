# Produce Release Notes When Cutting The First Tagged Release

## Summary

`CHANGELOG.md` and the `changelog-check` CI gate were removed on 2026-07-28 because the repository has no git tags: cocogitto had a single `Unreleased` bucket holding all 899 commits, 58% of which were `docs`/`refactor`/`chore`/`ci`/`test`/`build`/`style` entries with no user-visible effect. The gate was also unsatisfiable — regenerating captures history only up to the previous commit, so the file went stale on every commit, and it was already stale at HEAD. GitHub CI never ran it; it was local `just ci` friction only.

This task captures what must happen at the first tagged release so the decision is not lost.

## Problem

Nothing currently produces user-facing release notes. `.github/workflows/release.yml` is tag-triggered and calls `softprops/action-gh-release@v3` with `files:` only — no `body`, `body_path`, or `generate_release_notes`, so a tag today publishes binaries with an empty release body.

Two decisions were deliberately deferred rather than guessed at:

1. **Commit-type filtering.** `cog.toml` still registers all 11 conventional types for changelog generation. Verified on cog 7.0.0: adding `omit_from_changelog = true` to a type's table entry removes its section. Without that edit, generating notes at release time reproduces the same noisy dump that motivated the removal.
2. **Where notes live.** Either regenerate a committed `CHANGELOG.md` per tag, or publish notes only in the GitHub release body and keep the repository free of a generated file.

## Fix Direction

When cutting the first release:

- Decide whether to filter `chore`, `style`, `ci`, `build`, `test`, and `refactor` out of generated notes via `omit_from_changelog = true` in `cog.toml`.
- Wire release notes into `.github/workflows/release.yml`, either with `generate_release_notes: true` or by generating with `cog changelog --at <tag>` and passing the result as `body_path`.
- `just changelog [range]` prints notes to stdout and takes an optional commit range or tag; it no longer writes a file. Use it to preview output before choosing.

Do not reintroduce a CI gate that diffs a generated file against all of `HEAD` — that is the shape that failed.

## Acceptance Notes

- The first tag publishes a GitHub release whose body lists user-visible changes.
- Generated notes exclude development-bookkeeping commit types, or the decision to keep them is recorded here.
- No verification gate requires a generated file to be regenerated on every commit.
