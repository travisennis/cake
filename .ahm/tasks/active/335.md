# Enforce Cyclomatic Complexity and CRAP Targets via Tooling and Guardrails

## Summary

Document the CC/CRAP targets from task #325 as project guardrails and
implement enforcement mechanisms that give agents (and human contributors)
early feedback when introducing high-complexity code.

Currently, the project has:
- `ci/cargo-crap-baseline.json` — CRAP regression check (green only if
  every function's CRAP is ≤ baseline × (1 + ε))
- `scripts/cargo-crap.sh` — wraps `cargo-crap` with baseline comparison
- `just cargo-crap-report` — runs the comparison and prints markdown

What's missing:
- **No CC gate at all.** CRAP tracks complexity × coverage, but a new
  function with CC 25 and no tests would pass CRAP regression if it
  has the same CRAP as the baseline — the baseline is full of high CC
  already. We need a CC cap for new/modified functions.
- **No clippy cognitive complexity configuration.** `.clippy.toml` only
  configures test allowances. Production code has no CC ceiling from
  clippy.
- **No pre-commit or pre-push check.** Enforcement is CI-only, after
  the work is done.
- **No AGENTS.md rule.** Agents get no instruction about complexity
  targets during the operating loop.

## Proposed Enforcement Layers

### 1. AGENTS.md operating loop addition

Add a verification step after `just ci` / before handoff that runs
`cargo-crap` on changed files and flags any function exceeding the CC
targets. This gives the agent immediate feedback during development,
not after CI fails.

### 2. Clippy cognitive complexity ceiling

Set `cognitive-complexity-threshold` in `clippy.toml` for production
code. Targets:
- Threshold 15 (warn by default, deny in CI)
- Per-function `#[allow(clippy::cognitive_complexity)]` for the few
  grandfathered functions with documented justification

But note: clippy's cognitive complexity is *not* the same as McCabe CC
used by `cargo-crap`. This layer gives a different signal — still
useful, but not a direct enforcement of the CC ≤ 10 target.

### 3. Per-function CC baseline in CI

Extend `scripts/cargo-crap.sh` (or the CRAP regression report) to also
flag any function whose McCabe CC exceeds the target thresholds from
#325. This would make the CI pipeline fail on new high-CC functions.

### 4. Pre-commit hook (optional, stretch)

Add a pre-commit hook that runs `cargo-crap` on staged `.rs` files and
warns on CC exceeds, with an opt-out via commit flag. Prevents
high-complexity code from entering the repo at all.

## Relevant Files

- `clippy.toml` — cognitive complexity threshold
- `scripts/cargo-crap.sh` — CRAP baseline comparison
- `ci/cargo-crap-baseline.json` — current baseline
- `justfile` — CI gate targets
- `AGENTS.md` — agent operating loop
- `src/` — individual functions needing `#[allow]` annotations
