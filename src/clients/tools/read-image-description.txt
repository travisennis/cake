Read an image file and return it to you as an image you can actually see. Supports PNG, JPEG, GIF, and WebP.

Behavior:
- Requires an absolute path to an existing file inside Cake's read grants: the working directory, a temp directory, a built-in toolchain or system path, a skill directory, or a configured read-only or writable directory (including one added with --add-dir). Credential-bearing paths remain denied even when a parent directory is granted.
- Detects the format from the file's leading bytes, not its extension. Files that are not images are rejected with a message pointing at Read for text files.
- Rejects source files larger than the configured read_image_max_bytes cap (default 32 MiB) with a clear error instead of sending them, so an oversized image never reaches the provider. A source whose header claims more than 100,000,000 decoded pixels is also rejected before a full decode.
- Returns the image inline as a base64 data URL; there is no upload step. An image that fits every request budget is sent byte for byte.
- Downscales an image whose longest edge exceeds 2048 px in memory before sending it, so a large screenshot or photo still reaches the provider; the source file is never modified. A downscaled PNG stays PNG and anything else becomes JPEG, except that transparency forces PNG; only the first frame of an animated GIF or WebP is kept.
- Each provider request also enforces the `[images]` count, pixel, and byte budgets. An image over a per-image limit is downscaled further, and when the whole request is over budget, older unpinned images are omitted and replaced with `[image omitted: ...]` markers. Session history and the source file keep the original image.

Guidance:
- Use ReadImage when a screenshot, diagram, chart, or photo is part of the question; Read rejects binary files.
- Prefer the smallest image that answers the question; a cropped region costs far fewer tokens than a full screenshot.
