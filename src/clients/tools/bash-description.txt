Execute a shell command in the host machine's terminal and return its output. Each call starts a new shell, so directory, environment, and other shell state do not carry over. Non-interactive commands only.

Commands run in the working directory by default. Use `cwd` to select an existing directory inside the working directory or one the sandbox grants. Relative paths resolve from the working directory, and `cwd` applies to one call.

`timeout` (default 60, range 1–60) is a yield window, not a kill deadline. A command still running when the window ends returns a session ID.
Use BashSession to read it instead of rerunning the command. For known long-running work, set `background: true`, continue with other calls, and use BashSession.
Sessions do not survive cake exit or resume. Do not append `&` to detach.

Guidance:
- Directories: Bash with ls, find, or tree.
- File contents: Read.
- Content search: rg via Bash.
- Edits: Edit, not sed.
- New files: Write, not echo.
- Do not prefix commands with `cd`; pass `cwd` on each call.
- Inside double quotes, the shell treats backticks and `$()` as command substitution before cake sees them.

`reason` is optional: one sentence stating the intended effect. Supply it for state-changing, destructive-looking, or remote-effect commands. It is an untrusted hint for the policy gate, not authorization; the gate sees only the command, so include any required check in it.
